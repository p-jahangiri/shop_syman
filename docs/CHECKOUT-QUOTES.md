# محاسبهٔ سروری خرید

شرح برش اولیهٔ 2026-10-22؛ سیاست هزینه و schema2 در [CHECKOUT-CHARGES.md](CHECKOUT-CHARGES.md) افزوده شده‌اند. شواهد شمارش‌شدهٔ این فایل مربوط به برش اولیه‌اند؛ STATUS آخرین شمارش را دارد. این بخش به API، SQL و checkout دو زبانه وصل است. سفارش، رزرو هنگام checkout، پرداخت و پروندهٔ اعتبار هنوز پیاده نشده‌اند؛ این محاسبه تضمین قیمت یا موجودی نیست.

## قرارداد

`POST /api/cart/{fa|en}/quote` همان هویت سبد را مصرف می‌کند: access token کامل عضو یا cookie مهمان HttpOnly. Origin مجاز الزامی است؛ دادهٔ خصوصی `private, no-store` است. Next فقط همین مسیر POST را به BFF سبد اضافه می‌کند؛ allowlist cookie/header، سقف۱۶KiB ورودی، schema سخت‌گیر و سقف۱MiB پاسخ دارد. credential پنل به API مشتری عبور نمی‌کند. درخواست قیمت، مبلغ پرداخت، شناسهٔ مالک یا سبد نمی‌پذیرد.

ورودی: `cartVersion` الزامی، `methodId` و `planId` اختیاری. برای ذخیرهٔ محاسبه با method، `requestId` از نوع UUID غیرصفر الزامی است؛ plan فقط با روش چکی معتبر قابل استفاده است. بدون method، پاسخ فهرست روش/طرح مجاز و مبلغ جاری است و سطر quote ذخیره نمی‌شود.

خروجی اولیه schema1 شامل اقلام snapshot، مبلغ هر خط، اصل کالا، افزوده، پیش‌پرداخت، جمع کالا با افزوده، مبلغ نسبی هر چک، روش/طرح مجاز و انتخاب‌شده، fingerprint، مهلت و blockerهاست. تمام مبالغ رشتهٔ صحیح ریال‌اند؛ basis point و شماره/فاصلهٔ ماه عدد صحیح‌اند. نام/برچسب/گارانتی زبان جاری و SKU/SellerId/PriceVersion در snapshot حفظ می‌شوند.

سبد فیزیکی `shippingRequired:true, shippingRial:null` دارد. سبد تماماً دیجیتال به ارسال فیزیکی نیاز ندارد و فقط در این حالت shipping برابر رشتهٔ `0` است. مالیات و مبلغ نهایی تا پیکربندی سیاست واقعی `null` می‌مانند؛ اکنون تنظیم صریح هزینه از پنل ممکن است و schema2 محاسبهٔ آن را حفظ می‌کند. ارسال/مالیات تعیین‌نشده، provider غیرفعال، تأیید اعتبار و نبود مسیر ثبت سفارش، blockerهای صریح‌اند؛ در این برش `canPlaceOrder:false` است. UI وجهی دریافت نمی‌کند و نشانی/مدرک جمع‌آوری نمی‌کند.

## قواعد و تراکنش

- Catalog فقط تنوع فعال کالای منتشرشده با دسته/برند فعال را از قرارداد `ICheckoutCatalogReader` منتشر می‌کند. Sales از context ماژول دیگر استفاده نمی‌کند.
- روش باید برای همهٔ محصولات و overrideهای تنوع مجاز باشد؛ محدودیت مبلغ روی جمع اصل کالا و محدودیت دسته روی همهٔ اقلام اعمال می‌شود. override خالی تنوع از محصول ارث می‌برد. طرح چک نیز enabled/بازه/دسته و انتساب محصول را رعایت می‌کند؛ انتساب خالی طرح، همهٔ طرح‌های عمومی واجد شرایط است.
- موجودی جاری همهٔ اقلام و نسخهٔ سبد دوباره بررسی می‌شوند؛ تغییر سبد، موجودی یا انتشار پاسخ409 می‌دهد. افزودن به سبد یا محاسبه رزرو ایجاد نمی‌کند.
- composition root یک Serializable متعلق به Sales را فقط در همان درخواست به Catalog/Inventory/Payments/Credit متصل می‌کند؛ queryها ترتیبی‌اند. قفل مشترک همان actor سبد تا commit مانع ویرایش بین خواندن نسخه و ذخیره است. session مهمان مصرف‌شده/منقضی حتی برای replay رد می‌شود.
- `(ActorKey, RequestId)` یکتا و قفل درخواست SQL است؛ hash payload شامل زبان/نسخه/روش/طرح است. درخواست تکراری همان snapshot و مهلت را برمی‌گرداند؛ payload متفاوت409 است. replay قیمت یا شروط تازه را جایگزین نمی‌کند؛ برای محاسبهٔ تازه UUID تازه لازم است. تغییر قیمت/شرایط باید هنگام ثبت سفارش آینده دوباره با fingerprint بررسی شود.
- مهلت فنی اولیه۵دقیقه است (A13)، قابل بازنگری و بدون تأیید سیاست تجاری. replay منقضی همان snapshot را با `quote_expired` برمی‌گرداند. endpoint خواندن quote با ID دلخواه وجود ندارد.
- هدر، خطوط و چک‌ها در سه جدول Sales با bigint و FK داخلی اتمیک ذخیره می‌شوند. JSON فقط projection ثابت replay است؛ اقلام/مبالغ رابطه‌ای نیز جدا ذخیره‌اند. حجم snapshot داخلی حداکثر۱MiB UTF16 و۵۱۲KiB UTF8؛ حداکثر۶۴ روش/طرح و۶۴ خط، بدون truncation. migration شانزدهم `CheckoutQuotes` و SQL idempotent Sales اعمال شده‌اند.

## محاسبهٔ چک

واحد گردکردن۱ یا۱۰ریال از پنل می‌آید. پیش‌پرداخت از درصد اصل کالا به بالا گرد و به اصل محدود می‌شود. افزوده روی ماندهٔ تأمین مالی با BigInteger محاسبه و به همان واحد به بالا گرد می‌شود. جمع کالا برابر اصل به‌علاوهٔ افزوده است؛ پیش‌پرداخت از جمع دوباره کم نمی‌شود. چک‌های میانی مضرب واحد و باقیماندهٔ دقیق در آخرین چک است. چک صفر ساخته نمی‌شود؛ مبلغ ناکافی برای چند چک خطای صریح است. پیش‌پرداخت۱۰۰٪ چک ندارد. خروجی بیش از bigint رد می‌شود. ماه‌ها فاصلهٔ نسبی‌اند؛ تاریخ قطعی و سیاست شمسی/تعطیلات هنوز تعیین نشده است.

## رابط و شواهد

checkout در API mode از پاسخ سرور روش/طرح و مبلغ می‌گیرد؛ preview قبلی جداست. token و quote فقط حافظه‌اند. تغییر هویت/زبان/سبد، پاسخ دیررس و محاسبهٔ قبلی را کنار می‌گذارد. timeout جایگزین نمونه ندارد؛ retry شکست ارتباط همان UUID و انتخاب جدید/محاسبهٔ موفق بعدی UUID تازه دارد. UI مهلت را نمایش و انقضا را مشخص می‌کند. مبلغ نهایی نامعلوم به جمع کالا تبدیل نمی‌شود.

- ۱۳۶ تست بک‌اند:۱۹ تازه شامل دقت محاسبه، overflow، تمام پیش‌پرداخت،۲۰۰ مقدار با شروط متفاوت و مرز Origin/هویت/MFA. `backend-tests.log`.
- ۴۱ SQL:۱۰ تازه شامل دو درخواست همزمان، replay پایدار، تغییر شرط/قیمت، جداسازی مهمان، نسخه/موجودی/انتشار، دیجیتال، بازگشت خطای child insert، expiry و مهمان منقضی/ادغام‌شده. `sql-tests.log`. این شاهد SQL Server واقعی محلی روی Rosetta است؛ Linux نهایی جدا لازم است.
- ۶۹ تست فروشگاه، typecheck و build تولیدی موفق. هفت تست تازه مبلغ بزرگ، تناقض پاسخ، چک، input injection و خطای سرویس را پوشش می‌دهند.
- ۱۷ HTTP واقعی Next→API→SQL در `checkout-quote-http.json`؛۱۴ HTTP سبد هم مجدداً پاس شدند. مهمان تست خالی شد؛ credential، cookie یا quoteId در گزارش ذخیره نیست. snapshotهای آزمون محلی با مهلت ثابت باقی می‌مانند.
- QA دستی CUA،۹ بررسی دسکتاپ: روش نقدی محدود به کالا، محاسبهٔ نقدی، طرح۶ماههٔ واقعی SQL در دو زبان، نامعلوم بودن هزینه‌ها، timeout/retry و ابطال محاسبه با ویرایش تب دیگر. `checkout-quote-ui.json` و `sayman-checkout-server-fa.png`.
- درخواست viewport۳۹۰×۸۴۴ در این اجرا به ابعاد واقعی صفحه اعمال نشد؛ اندازهٔ مشاهده‌شده۱۲۸۰×۷۲۰ با clientWidth=scrollWidth=۱۲۶۵ بود. QA جدید موبایل پذیرفته نشده؛ این شاهد صرفاً نبود overflow دسکتاپ است. screenshot fullPage ابزار هم برای RTL تصویر ناقص ساخت و با screenshot معمول معتبر جایگزین شد. override reset شد. پس از QA، هر دو پورت۳۱۰۵/۵۱۸۱، تب‌های آزمایش، دیتابیس موقت و credential/کلیدهای تولیدی harness پاک شدند؛ حساب اصلی و MFA استفاده نشدند.

## ادامه

سفارش snapshotدار و اعتبارسنجی دوبارهٔ quote/actor/version/fingerprint/expiry، آدرس و ارسال/مالیات قابل پیکربندی، اتصال رزرو داخلی، کنترل پرداخت دیررس و پروندهٔ چک مراحل بعدند. سیاست نگهداری/پاک‌سازی cart و quote، محدودیت ظرفیت ذخیرهٔ مهمان، بار/بن‌بست زیر فشار، pagination تنظیم روش/طرح، QA موبایل واقعی و Linux همچنان بازند. providerهای D16 غیرفعال می‌مانند؛ تمام پروژه کامل اعلام نمی‌شود.
