# طراحی و عملکرد فروشگاه

## جلوه‌های حرکت — D109

در «محتوا و تنظیمات ← تنظیمات فروشگاه ← طراحی و رفتار فروشگاه ← جلوه‌های حرکت»، سبک **بالاآمدن نرم**، **درخشش قاب** یا **موج نور** را انتخاب کنید. شدت حرکت و روشن یا خاموش بودن هر بخش جدا تنظیم می‌شود: بنرها، کارت‌های کالا و پنل فیلتر. «پخش نمونهٔ حرکت» فقط نمونهٔ همان فرم را اجرا می‌کند. برای تغییر فروشگاه، پیش‌نویس را ذخیره و منتشر کنید.

قاب بنر اصلی یک‌بار کوتاه حرکت می‌کند؛ قاب بنرهای دیگر و کارت‌ها هنگام هاور یا فوکوس، و پنل فیلتر هنگام بازشدن جلوه می‌گیرند. تصویر و محتوای اصلی خانه برای شروع حرکت منتظر نمی‌مانند. انتخاب «خاموش» یا ترجیح کاهش حرکت دستگاه، اجرای جلوه را متوقف می‌کند. [شواهد D109](changelog/D109.md).

## ترکیب‌های تازه و منوی یکپارچه — D108

در حالت ساده و کپسولی، لینک‌های عادی یک سطح مشترک دارند. خط زیر و رنگ خوانا، حالت فعال را نشان می‌دهند؛ در حالت کپسولی زمینهٔ ملایم فقط هنگام تعامل یا برای پیوند فعال دیده می‌شود. دو میان‌بر خرید چکی و کارکرده قاب هم‌شکل دارند. پنج نمونهٔ رنگ بازتنظیم شدند و هر نمونه، ردیف روشن و تاریک خودش را در پنل نشان می‌دهد. رنگ‌های قبلاً منتشرشده با بازتنظیم نمونه عوض نمی‌شوند؛ برای استفاده از ترکیب تازه، نمونه را دوباره انتخاب، ذخیره و منتشر کنید. [شواهد D108](changelog/D108.md).

## پالت‌های آماده و تنوع بخش‌ها — D107

در «محتوا و تنظیمات ← تنظیمات فروشگاه ← رنگ فروشگاه» از میان بهار شکوفه، تابستان ساحلی، پاییز زعفرانی، زمستان بلور و امضای سایمان انتخاب کنید. نمونه رنگ‌های هر دو تم را در پیش‌نویس می‌گذارد؛ شدت تنوع و رنگ هر بخش را بعد از انتخاب هم می‌توانید تغییر دهید. پیش‌نمایش، نوار منو، بنر، پنج کارت، کمپین و پانوشت را جداگانه نشان می‌دهد. سپس پیش‌نویس را ذخیره و منتشر کنید. تغییر فصل خودکار نیست.

پالت آماده به رنگ‌های قرارداد موجود CMS تبدیل می‌شود؛ شناسهٔ نمونه ذخیره نمی‌شود. بنابراین تغییر احتمالی نمونه در سورس، پالت قبلاً منتشرشده را تغییر نمی‌دهد. طیف‌ها در چیدمان کارت‌ها نوبتی‌اند تا کارت‌های مجاور در شبکه‌های دو تا چهار ستونی هم‌رنگ نشوند. دکمهٔ اصلی همان رنگ انتخابی و متن محاسبه‌شده را دارد؛ منو، قاب تصویر، بنرها و نوار پایان طیف نقش خود را می‌گیرند. [شواهد D107](changelog/D107.md).

## پایهٔ تفکیک رنگ و سطوح — D106

در «محتوا و تنظیمات ← تنظیمات فروشگاه ← رنگ فروشگاه»، رنگ اصلی، شدت رنگ خودکار و رنگ بخش‌ها را برای تم روشن و تاریک تنظیم کنید. همان پالت منتشرشده برای هر دو زبان خوانده می‌شود. رنگ اصلی روی دکمه‌ها حفظ می‌شود و متن خوانا به‌صورت خودکار انتخاب می‌شود. زمینه، کارت و قاب تصویر هر کدام بازهٔ روشنی جدا دارند؛ خط دور کارت هم از همان پالت محاسبه می‌شود. انتخاب یک رنگ برای همهٔ بخش‌ها مرز کارت را حذف نمی‌کند.

پیش‌نمایش پنل نمونهٔ همین سطوح و رنگ متن دکمه را نشان می‌دهد. برای اصلاح ظاهر فعلی نیازی به پاک‌کردن یا ثبت دوبارهٔ پالت ذخیره‌شده نیست. [وضعیت نسخهٔ جاری](STATE.md) و [شواهد بازطراحی](changelog/D106.md).

## سابقهٔ پایهٔ طراحی — D55

تاریخ: 2026-10-29. این سند قرارداد طراحی مینیمال و شیشه‌ای فروشگاه سایمان، کنترل‌های مدیر و حدود شواهد عملکرد را شرح می‌دهد. نسخهٔ جاری همان فروشگاه 3000، API 5080 و پنل 3173 با دیتابیس Sayman است؛ نسخهٔ اجرایی جدا ساخته نمی‌شود. [STATUS](STATUS.md) و descriptor های current مرجع انتشار نهایی‌اند. این برش به معنی تکمیل کل پروژه یا انتشار Production نیست.

runtime نهایی این تحویل: فروشگاه `storefront-runtime-quality-04be57b87b804804b4594a401b1f85d1`، پنل `admin-runtime-quality-4bb06ca5d5554816839cb7bd70a1b76c` و API `api-runtime-appearance-2bec55592ee04725bee0248fde2ed532` در `tmp/`. شمارهٔ migration دیتابیس 85 است؛ این برش migration تازه ندارد.

## کنترل ظاهر از پنل

در «محتوا و تنظیمات»، سند تنظیمات فروشگاه (`site`) و زبان موردنظر را باز کنید. بخش «طراحی و رفتار فروشگاه» شش کنترل دارد:

| کنترل | مقدارهای مجاز | پیش‌فرض | اثر |
|---|---|---|---|
| `surface` | `glass` / `solid` | `glass` | سطح شیشه‌ای با شفافیت محدود، یا سطح یکدست |
| `density` | `comfortable` / `compact` | `comfortable` | فاصلهٔ باز یا فشردهٔ بخش‌ها و کارت‌ها |
| `corners` | `rounded` / `soft` | `rounded` | گوشه‌های گرد یا با انحنای کمتر |
| `motion` | `subtle` / `none` | `subtle` | حرکت کوتاه و ملایم، یا حذف انیمیشن تزئینی |
| `heroLayout` | `split` / `compact` | `split` | معرفی دوقسمتی با تصویر، یا معرفی فشرده‌تر |
| `stickyHeader` | `true` / `false` | `true` | هدر در دسترس هنگام پیمایش، یا هدر معمولی |

این مقادیر در `site.appearance` قرار می‌گیرند. سندهای قبلی که این فیلد یا بخشی از آن را ندارند، همان پیش‌فرض‌ها را دریافت می‌کنند؛ مقدار صریح `false` حفظ می‌شود. دکمهٔ «بازگشت طراحی به پیش‌فرض» تنظیم appearance را برمی‌دارد و لوگو، رنگ، متن یا محتوای سند را پاک نمی‌کند. تنظیم رنگ، فونت، لوگو، معرفی ابتدای صفحه، بنرها و بلوک‌های صفحهٔ اصلی همچنان در همان CMS موجود است.

ابتدا پیش‌نویس را ذخیره و سپس همان سند را منتشر کنید. ذخیره به‌تنهایی فروشگاه عمومی را عوض نمی‌کند. تنظیمات فارسی و انگلیسی مستقل‌اند؛ تغییر سند فارسی خودکار به انگلیسی کپی نمی‌شود. پس از انتشار، هر زبان را در موبایل و دسکتاپ و حالت روشن/تیره بررسی کنید. پیش‌نمایش پنل شماتیک است و جای بررسی صفحهٔ واقعی را نمی‌گیرد.

تغییر طراحی به مجوز مدیریت محتوا و گردش معتبر فعلی CMS نیاز دارد؛ این بخش دسترسی کاربر را بیشتر نمی‌کند. API و قرارداد فروشگاه مقدارهای محدود را اعتبارسنجی می‌کنند و CSS، HTML، اسکریپت دلخواه یا کلید ناشناخته نمی‌پذیرند. تغییر طرح به migration یا تغییر سیاست مالی نیاز ندارد. [شاهد اعتبارسنجی و SQL](../artifacts/checks/d55-cms-appearance-backend-tests.json) شامل 48 آزمون واحد و 3 fixture کوتاه‌عمر SQL است؛ پس از بررسی، هیچ دیتابیس آزمایشی باقی نماند.

[آزمون جدایی پیش‌نویس](../artifacts/checks/d55-draft-isolation.json) ثابت کرد ذخیرهٔ پیش‌نویس ظاهر عمومی را تغییر نمی‌دهد. [انتشار تنظیم جایگزین](../artifacts/checks/d55-cms-live-alternate.json) تغییر فقط appearance و اعمال هر شش ویژگی SSR را ثبت کرد؛ این گزارش، انتخاب تجاری دائمی آن طرح آزمایشی نیست. وضعیت نهایی سند در STATUS ثبت می‌شود.

## حرکت، شیشه و دسترس‌پذیری

ظاهر از ویژگی‌های `data-shop-*` روی HTML سرور اعمال می‌شود و برای شروع نمایش منتظر افکت JavaScript نمی‌ماند. کارت‌ها سطح و سایهٔ سبک دارند؛ blur روی همهٔ کارت‌ها تکرار نشده است. blur پس‌زمینه فقط هدر و نوار پایین موبایل، با سقف 14px و زیر `@supports` فعال می‌شود؛ انتخاب `solid` آن را کنار می‌گذارد. بدون پشتیبانی مرورگر، سطح پایهٔ خوانا باقی می‌ماند.

حرکت‌ها کوتاه‌اند و عمدتاً transform/opacity را تغییر می‌دهند؛ حرکت تزئینی دائمی و حلقهٔ انیمیشن JavaScript اضافه نشده است. انتخاب `motion=none` انیمیشن، transition و پیمایش نرم را قطع می‌کند. ترجیح سیستم `prefers-reduced-motion: reduce` حتی با انتخاب `subtle` اولویت دارد. طراحی دو زبان، ترتیب RTL/LTR، فوکوس، متن زندهٔ نام فروشگاه و جریان معتبر خرید حفظ می‌شوند؛ پوشش کامل WCAG یا همهٔ دستگاه‌ها از این برش نتیجه نمی‌شود.

## کاهش هزینهٔ بارگذاری

لوگوی منتخب هنگام نمایش کوچک هدر/فوتر از نسخهٔ 128px WebP با حجم **6,366 بایت** استفاده می‌کند؛ PNG اصلی **141,190 بایت** است. کاهش حدود 95.5٪ فقط برای همین دارایی است و به معنی همین مقدار کاهش حجم کل صفحه نیست. فایل اصلی و آیکون‌های نصب حفظ‌اند؛ لوگوی دلخواه CMS همچنان اولویت دارد و فقط مسیر شناخته‌شدهٔ نشان سایمان به نسخهٔ کوچک نگاشت می‌شود.

تصاویر اصلی hero، جزئیات کالا و جلد مقاله، وقتی نامزد LCP هستند، eager و با اولویت بالا بارگیری می‌شوند. تصویرهای پایین صفحه lazy می‌مانند. `sizes` در تصاویر مناسب، اندازهٔ نمایش واکنش‌گرا را به Next اعلام می‌کند؛ عرض/ارتفاع و نسبت تصویر برای رزرو فضا حفظ می‌شوند. تصاویر عمومی آپلودشده از سه مسیر صادرشدهٔ thumb/card/zoom استفاده می‌کنند و URL خارجی CMS همچنان توسط مرورگر خوانده می‌شود، نه یک fetch نامحدود سرور.

حدهای 320/960/1920 در پردازش رسانه **بیشینهٔ ضلع** هستند؛ تصویر کوچک بزرگ‌نمایی نمی‌شود و جهت/نسبت اولیه حفظ می‌شود. این اعداد لزوماً عرض واقعی فایل نیستند؛ بنابراین descriptor های ساختگی `320w/960w/1920w` به srcset اضافه نشده‌اند. تصویر zoom جزئیات در تعامل بزرگ‌نمایی مصرف می‌شود، بدون اجبار آن به نمایش اولیهٔ کارت.

واکشی محتوای صفحهٔ CMS در metadata و بدنه با React.cache در همان درخواست مشترک است. گرم‌کردن کاتالوگ آفلاین PWA بعد از load و زمان idle انجام می‌شود، فقط زبان جاری را می‌گیرد و رویدادهای هم‌زمان شروع را ادغام می‌کند. در صفحهٔ حساس، تب مخفی، Save-Data یا اتصال 2G این کار اختیاری انجام نمی‌شود؛ خروج از component درخواست را لغو می‌کند و بازگشت شبکه امکان تازه‌سازی دارد. کش دادهٔ حساب، سفارش، سبد و پرداخت فعال نشده است. فونت‌های خودمیزبان موجود حفظ شده‌اند؛ کتابخانهٔ انیمیشن یا فونت شبکه‌ای تازه اضافه نشده است.

بازبارگذاری با حفظ موقعیت پیمایش یک نقص واقعی را آشکار کرد: fallback کوتاه `app/[locale]/loading.tsx` می‌توانست فوتر را پیش از محتوای اصلی نشان دهد و هنگام رسیدن صفحه آن را جابه‌جا کند؛ در آن سناریو CLS=0.74 ثبت شد. loading عمومی حذف و همان حالت انتظار به `account/loading.tsx` و Suspense حساب محدود شد. در HTML نهایی هر دو زبان، محتوای صفحهٔ اصلی پیش از بخش اعتماد و فوتر می‌آید؛ بررسی دوبارهٔ حفظ موقعیت پیمایش CLS=0 نشان داد. این اصلاح، حالت انتظار معتبر حساب را حذف نمی‌کند.

## سئو و امکان ایندکس

محیط محلی عمداً noindex باقی می‌ماند. ایندکس نیازمند همهٔ این شروط است: `SHOP_PUBLIC_URL` معتبر HTTPS و غیرمحلی، `SHOP_ENABLE_INDEXING=true`، دادهٔ واقعی API، نبودن preview و اجازهٔ منتشرشدهٔ `site.seo.allowIndexing` در زبان مربوط. تغییر طراحی هیچ‌کدام را روشن نمی‌کند؛ دامنه و پذیرش Production هنوز موضوع استقرار واقعی‌اند.

canonical از origin مورداعتماد تنظیمات ساخته می‌شود، نه Host ورودی. فیلتر و جست‌وجوی غیر canonical، مسیرهای خصوصی و صفحات واقعاً ناموجود قواعد قبلی noindex/404/503 را حفظ می‌کنند. Product JSON-LD نیز به گیت ایندکس مقید است و وضعیت واقعی نو/کارکرده و مبلغ دقیق IRR را نشان می‌دهد؛ امتیاز یا نظر فرضی تولید نمی‌کند. HTML مقاله و صفحهٔ CMS فقط زبان منتشرشده‌ای را معرفی می‌کند که همان درخواست تأیید کرده است؛ ترجمه‌های واقعاً منتشر و مجاز به‌صورت متقابل در sitemap XML ثبت می‌شوند، بدون زنجیرهٔ درخواست اضافه برای metadata.

تکمیل فنی به تنهایی رتبهٔ صفحهٔ اول را تضمین نمی‌کند. انتشار HTTPS واقعی، محتوای اصیل و مفید هر محصول/دسته، موجودی و اطلاعات دقیق، دسترسی خزنده، ثبت و پایش Search Console و شواهد کاربران واقعی هنوز برای ارزیابی نتیجه لازم‌اند.

## شواهد و محدودیت اندازه‌گیری

در [اندازه‌گیری نهایی Chrome DevTools](../artifacts/checks/d55-final-chrome-local-metrics.png)، صفحهٔ محلی `/fa` از بالای صفحه روی دسکتاپ **LCP=0.16s، CLS=0 و INP=32ms** نشان داد؛ تعامل INP تغییر حالت روشن/تیره بود. در [بازبارگذاری با حفظ موقعیت پیمایش](../artifacts/checks/d55-final-retained-scroll-metrics.png)، **LCP=0.19s و CLS=0** دیده شد. عدد INP=0 در تصویر دوم، به معنی سنجش معنادار پاسخ‌گویی همهٔ تعامل‌ها نیست.

CPU و شبکه روی No throttling بودند و شرایط کش به‌صورت سناریوی کنترل‌شده تثبیت نشده بود. این مشاهده‌های محلی، آمار میدانی، آزمون استاندارد cold-cache، نتیجهٔ موبایل ضعیف یا تضمین همین سرعت در میزبانی عمومی نیستند. CLS=0 در این اجرا نیز ادعای نبودن هر تغییر چیدمان در همهٔ مسیرها و تعامل‌ها نیست. مشاهدهٔ قدیمی LCP=0.50s/CLS=0.00/INP=64ms تاریخی است؛ اختلاف اعداد، benchmark کنترل‌شدهٔ قبل/بعد محسوب نمی‌شود.

در نشست نهایی Chrome، Console خطا و هشدار نداشت و Issues صفر بود؛ یک پیام اطلاعاتی مربوط به نصب PWA باقی بود. تصاویر [روشن](../artifacts/checks/d55-final-storefront-light.png) و [تیره](../artifacts/checks/d55-final-storefront-dark.png) نمای نهایی دسکتاپ را ثبت می‌کنند. تصاویر موبایل [فارسی](../artifacts/checks/d55-final-mobile-fa.png) و [انگلیسی](../artifacts/checks/d55-final-mobile-en.png) در نمای 375×667 پیش از اصلاح محدود loading گرفته شدند؛ ظاهر آن اصلاح تغییر نکرد. این بررسی، استفاده از دستگاه واقعی موبایل یا اندازه‌گیری عملکرد موبایل نیست.

[پذیرش نهایی HTTP](../artifacts/checks/d55-final-http-acceptance.json) شامل 61 بررسی موفق، هر دو زبان، ترتیب SSR، ویژگی‌های ظاهر، ابعاد تصویر، معنای فیلد جست‌وجو و noindex محلی است. [بررسی محدود SEO/PWA](../artifacts/checks/d55-seo-performance-scope.json) 47 آزمون مرتبط، TypeScript و ESLint/Prettier همان فایل‌ها را ثبت می‌کند. [انتشار رابط‌ها](../artifacts/checks/frontend-quality-4bb06ca5d5554816839cb7bd70a1b76c-main-release.json) و [انتشار نهایی فروشگاه](../artifacts/checks/frontend-quality-04be57b87b804804b4594a401b1f85d1-main-release.json) شواهد جدا دارند؛ شمارش آزمون محدود جای کل آزمون‌های پروژه نیست. runtime دارایی‌های قدیمی را برای نشست‌های باز حفظ می‌کند؛ جمع حجم همهٔ فایل‌های static آن، حجم JavaScript بارگیری‌شدهٔ یک صفحه محسوب نمی‌شود.

پذیرش باقی: اندازه‌گیری کنترل‌شده روی شبکه و CPU محدود، مرورگرها و دستگاه‌های واقعی، cold/warm cache، مسیرهای کالا/فیلتر/خرید، دادهٔ میدانی Production و آستانه‌های Core Web Vitals در ترافیک واقعی. هدف راهنمای Google، LCP حداکثر 2.5s، INP کمتر از 200ms و CLS کمتر از 0.1 است؛ مشاهدهٔ محلی جای این ارزیابی را نمی‌گیرد.

## منابع اصلی بررسی‌شده

- [Google Search Central — Core Web Vitals](https://developers.google.com/search/docs/appearance/core-web-vitals): معیارهای بارگذاری، پاسخ‌گویی و ثبات صفحه و نیاز به شواهد میدانی.
- [Chrome — اولویت تصاویر](https://developer.chrome.com/docs/modern-web-guidance/guides/performance/optimize-image-priority): تصویر LCP نباید lazy باشد و اولویت بالا باید محدود به تصاویر واقعاً مهم بماند.
- [Next.js — فونت‌ها](https://nextjs.org/docs/app/getting-started/fonts): میزبانی محلی و بهینه‌سازی بارگیری فونت. راهنمای محلی نسخهٔ نصب‌شدهٔ Next16 برای Image، metadata و lazy loading نیز پیش از تغییر خوانده شد.
- [Chromium — هشدار تصویر lazy با ابعاد صفر](https://chromium.googlesource.com/devtools/devtools-frontend/+/e5a712cbc994ff348582e3beac398136ca992a83%5E%21/): هشدار تازه می‌تواند به اندازهٔ محاسبه‌شده یا نسبت CSS مربوط باشد، حتی وقتی بررسی HTTP وجود ویژگی‌های HTML را تأیید می‌کند.
