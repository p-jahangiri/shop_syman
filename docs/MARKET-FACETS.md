# فیلتر دسته و برند بازار

وضعیت 2026-10-25: این برش روی API، فروشگاه و پنل محلی اصلی منتشر است. تعداد migrationها همچنان ۴۲ است و هیچ جدول یا دادهٔ اصلی تغییر نکرد. مرجع انتشار `artifacts/checks/market-facets42-main-release.json` و نقطهٔ ادامه [STATUS](STATUS.md) است.

## رفتار

گزینه‌های دسته و برند از تمام مدل‌های مجاز بخش بازار در SQL محاسبه می‌شوند؛ وابسته به کارت‌های صفحهٔ جاری یا فهرست کالاهای قابل فروش نیستند. Count تعداد مدل است، نه ماندهٔ انبار یا تضمین تأمین. جست‌وجوی فارسی و انگلیسی همان یکسان‌سازی قبلی را دارد. اعتبار و قیمت مرجع منبع، قواعد قبلی خود را حفظ می‌کنند؛ انقضای مشاهده، مدل را از کاتالوگ حذف نمی‌کند.

شمارندهٔ هر selector، انتخاب خودش را کنار می‌گذارد و جست‌وجو و selector دیگر را حفظ می‌کند. برای مثال در دستهٔ گوشی و با انتخاب Apple، فهرست برندها همچنان برندهای دیگر همان دسته را نشان می‌دهد؛ فهرست دسته‌ها مدل‌های برند Apple را می‌شمارد. هر دو خواندن search و facets از predicate مشترک انتشار/صلاحیت مدل استفاده می‌کنند. Draft/Hidden، مدل نامعتبر یا دیجیتال، دسته/برند غیرفعال، مدل دارای پیشنهاد فروشگاهی با ماندهٔ آزاد و دادهٔ نمونه خارج Development وارد شمارنده نمی‌شوند.

عملیات گروه‌بندی، مرتب‌سازی و محدودسازی در SQL اجرا می‌شود. هر فهرست حداکثر ۲۰۰ گزینه دارد و flag محدودشدن در رابط توضیح داده می‌شود. گزینهٔ منتخبِ دارای نتیجه در اولویت است، حتی اگر در ترتیب عادی پس از گزینهٔ ۲۰۰ باشد. انتخاب بدون نتیجه در فرم باقی می‌ماند و صفر نشان می‌دهد؛ نام برندِ بدون نتیجه با شناسه نمایش داده می‌شود. دسته از متادیتای ترجمه‌شدهٔ فعلی فروشگاه نام می‌گیرد و در صورت نبود آن، شناسه آشکار است. فهرست خالی به برندهای صفحه یا کالاهای فروشگاهی جایگزین نمی‌شود.

فهرست مدل‌ها و facets دو خواندن تازه و مستقل‌اند؛ یک snapshot تراکنشی مشترک ادعا نمی‌شود و هم‌زمان با ویرایش مدیر ممکن است لحظه‌ای متفاوت باشند. شمارنده راهنمای محدودکردن جست‌وجو است؛ خرید و رزرو همچنان به قرارداد و بررسی سروری خودشان وابسته‌اند.

## API و رابط‌ها

`POST /api/market/{fa|en}/facets` عمومی است و همان `MarketSearchInput` قبلی را می‌پذیرد: query، categoryId، brandId، page و pageSize. صفحه و اندازه برای سازگاری اعتبارسنجی می‌شوند ولی عضو و شمارندهٔ facets را محدود نمی‌کنند. پاسخ schemaVersion=1 شامل locale، scope با query خام و categoryId/brandId صریحاً nullable، categories[{id,count}]، brands[{id,name,count}] و moreCategories/moreBrands است. فیلد SKU/Stock/پرداخت یا قیمت ندارد. قرارداد `/search` بدون تغییر مانده است.

Next همان مسیر `/api/market/{locale}/facets` را proxy می‌کند. محدودیت ۴KiB ورودی، ۲MiB خروجی، UTF-8/JSON معتبر، مهلت ۸ ثانیه، منع redirect، origin دقیق، عدم ارسال cookie/bearer/admin authority و no-store/noindex برقرار است. decoder تولیدی ساختار، حد و یکتایی گزینه‌ها و تطبیق scope و locale با درخواست را بررسی می‌کند. دادهٔ بازار وارد cache آفلاین نمی‌شود.

فرم FA/EN برند و دسته را با تعداد نمایش می‌دهد؛ روش GET معمولی پیش از hydration نیز قابل استفاده است. جست‌وجو/سایز/برند در تغییر زبان و صفحه‌بندی حفظ می‌شوند؛ ارسال فرم همیشه به صفحهٔ اول می‌رود. توضیح تعداد مدل در هر دو زبان آشکار است.

پنل `/api/admin/market` پارامتر اختیاری `brandId` را کنار فیلترهای قبلی دارد. مجوز catalog.read و MFA تغییر نکرده است. cursor به برند هم مقید است؛ انتقال cursor به برند دیگر یا برداشتن برند خطای ۴۰۰ می‌دهد. مسیر و cursor بدون برند با قرارداد قدیمی سازگار مانده‌اند. فهرست برندهای پنل از متادیتای مجاز Catalog است و موارد غیرفعال را مشخص می‌کند؛ فهرست عمومی فقط مدل‌های قابل نمایش بازار را می‌شمارد.

## پذیرش

- ۸۲۶ آزمون واحد، ۴۹۷ آزمون SQL واقعی، ۳۱۶ آزمون فروشگاه و ۱۹۰ آزمون پنل، typecheck و build هر دو رابط موفق‌اند. ۱۳DLL API با unit/SQL/harness برابر است. چهار SQL تازه شمارندهٔ مستقل از صفحه، فیلتر متقابل، فارسی، عدم نشت، ۲۰۵ گزینه، حفظ انتخاب آخر، cursor برند، مجوز و ورودی نامعتبر را پوشش می‌دهند.
- ۱۱ پاسخ خام HTTP روی SQL موقت با hash و decoder تولیدی، بدون دستکاری JSON پذیرفته‌اند: `market-facets-sql-wire/acceptance.json`. verifier ابتدا تعداد را ۱۲ فرض کرده بود؛ با فهرست دقیق ۱۱ نام واقعی اصلاح شد؛ decoderها تغییر نکردند.
- مرورگر در GUID تازهٔ خود QA: ورود مدیر/MFA تولیدشدهٔ خودش، تغییر برند مدل A در پنل از Samsung به Apple، فیلتر Apple از صفر به یک و Samsung به دو نتیجه، مشاهدهٔ همان تعداد در فروشگاه با فقط یک کارت در صفحه، صفحهٔ دوم، برگشت به صفحهٔ اول با تغییر برند، حفظ زبان و فیلتر، حالت خالی/clear و ترتیب Tab پذیرفته‌اند. فقط یک audit ویرایش ثبت شد؛ سفارش/رزرو/سیاست مالی/درخواست تأمین صفر و Stock101/0/0 ماند. سپس همان GUID، کلید و credential حذف شدند. `market-facets-browser-{acceptance,observations,sql}.json` شاهدند.
- اندازهٔ واقعی دسکتاپ ۱۲۸۰، client/scroll هر دو ۱۲۶۵، بدون overflow در دو رابط و console هر دو خالی بود. تصاویر viewport FA/EN/admin ذخیره‌اند. **پذیرش موبایل، screen reader کامل و CWV ادعا نشده‌اند.**
- انتشار اصلی بدون migration/seed یا انتقال نمونهٔ QA انجام شد. تمام ۱۲۱ fingerprint جدول، schema، تاریخچهٔ ۴۲ migration و تنظیمات/مانده‌ها پیش و پس از HTTP و مرورگر برابرند. ۱۸۹۵ خواندن HTTP شامل بازاجرای ۱۳۳۷ بررسی قبلی، assetهای قدیم/جدید و چهار POST عمومی فقط facets موفق‌اند. چهار پاسخ خام اصلی API/BFF در FA/EN با decoder تولیدی پذیرفته‌اند. مرورگر اصلی هم شمارندهٔ سه مدل قدیمی Samsung را نشان داد؛ انتخاب‌های قبلی مرورگر منتقل یا حذف نشدند.

بیلد اول Next در sandbox بدون پیشرفت ماند؛ فقط helper همان بیلد با SIGTERM متوقف و با مجوز worker محلی دوباره ساخته شد. اتصال SQL sandbox نیز ابتدا بسته بود؛ آزمون پذیرفته با SQL واقعی loopback اجرا شد. query گزارش QA ابتدا نام رزروشدهٔ schema `identity` را quote نکرده بود؛ فقط helper خواندنی اصلاح شد. هیچ‌کدام اتصال ساختگی، ضعیف‌کردن اعتبارسنجی یا تغییر داده برای پاس‌کردن آزمون نبود.
