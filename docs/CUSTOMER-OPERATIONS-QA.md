# پذیرش متصل دفتر نشانی و سفارش موقت

وضعیت 2026-10-23: **۴۷ بررسی مرورگر متصل موفق**؛ شاهد قبلی SQL۱۲۹ و storefront۱۱۶ محفوظ است. این برش از Next/BFF تا SQL با دادهٔ مصنوعی اجرا شد؛ اصلی۱۷ و سورس۲۱ باقی است. پرداخت واقعی و همهٔ معیارهای PDF پذیرفته نشده‌اند.

## دامنهٔ بررسی

1. harness مستقل SaymanTest_Ui با مشتری و مدیر/MFA تولیدشدهٔ خودش؛ هیچ credential مالک خوانده یا ثبت نشود. providerهای واقعی غیرفعال و محیط فقط loopback باشد.
2. دفتر نشانی فارسی/انگلیسی: ساخت با ارقام فارسی، default، ویرایش و حذف صریح، حفظ انتخاب و خطا، عدم افشای دفتر حساب دیگر. فقط نام/شماره/نشانی مصنوعی QA وارد شود؛ مقادیر خصوصی در گزارش درخواست ثبت نشوند.
3. تغییر صریح هزینه و فعال‌سازی سفارش موقت صرفاً در دیتابیس QA؛ هیچ نرخ/رایگان یا شرایط واقعی اصلی فرض نشود. خرید نقدی آنلاین انتخاب شود؛ canPay=false و gateway_unconfigured حفظ شوند.
4. سبد فیزیکی، quote3، کپی صریح دفتر به فرم، note/رضایت، ثبت سفارش پرداخت‌نشده، خالی‌شدن سبد، مشاهدهٔ snapshot و رزرو در پنل/مشتری، ویرایش دفتر بدون تغییر سفارش و لغو با آزادسازی رزرو بدون کاهش OnHand.
5. سفارش صرفاً دیجیتال بدون delivery/ارسال فیزیکی؛ دو زبان و موبایل در دامنهٔ واقعاً مشاهده‌شده؛ خطا/نتیجهٔ نامعلوم و تکرار فقط اگر در همین اجرا به شکل قابل اثبات تزریق/آزموده شد.
6. شواهد دقیق، اصلاح‌های لازم، تست مرتبط و cleanup graceful دیتابیس/کلید/credential/process/tab متعلق به همین run؛ main و Redis چت تغییر نکنند. پذیرش تولید/پرداخت واقعی/ارسال/کل PDF از این برش نتیجه نمی‌شود.

## مجوز تنظیمات QA

D21: مالک صریحاً مقادیر نمونه را فقط برای همین دیتابیس موقت مجاز کرد: ارسال۱۲۳۴۵ریال، بدون مالیات جداگانه، رزرو۶۰دقیقه و سقف۲ سفارش. بررسی خودکار ذخیره را پیش و پس از اثبات SQL isolation رد کرده بود؛ بعد از پرسش محدود، پاسخ «بله؛ فقط برای دیتابیس موقت QA» دریافت شد. سیاست فروشگاه اصلی تعیین‌نشده باقی است.

## نتیجه

گزارش `artifacts/checks/customer-operations-ui.json` شامل۴۷ بررسی موفق، صفر شکست و صفر console error در دو رابط است. دیتابیس دقیق متعلق به این اجرا `SaymanTest_Ui_98e08e9bc6c941d3a7acdca5ff5c6db0` بود؛ SQL DMV اتصال PID20904/API5181 به همین دیتابیس را اثبات کرد. هیچ credential یا MFA مالک مصرف نشد.

- دفتر نشانی: ورود مشتری موقت، ساخت با ارقام فارسی و نرمال‌سازی شماره/کدپستی، اولین default، ساخت دوم/default صریح، ویرایش و بازخوانی پس از reload، حذف تأییدشده و ارتقای تنها نشانی باقی‌مانده در FA/EN موفق‌اند.
- فیزیکی: quote3 برای یک iPhone با اصل۶۸۹۰۰۰۰۰۰ریال و ارسال۱۲۳۴۵ریال، جمع دقیق۶۸۹۰۱۲۳۴۵ریال/۶۸٬۹۰۱٬۲۳۴٫۵تومان داشت. کپی صریح از دفتر، حفظ یادداشت و رضایتِ هنوز انتخاب‌نشده بررسی شد. SM-1 پرداخت‌نشده، سبد خالی و مانده۵/رزرو۱/آزاد۴ ایجاد شد. ویرایش دفتر پس از سفارش، snapshot نشانی قبلی را تغییر نداد. لغو مشتری مانده۵/رزرو۰/آزاد۵ داد؛ تاریخچهٔ فیزیکی فقط رویداد seed داشت.
- دیجیتال: فقط در همین QA یک کالای seed به «QA digital entitlement»/«کالای دیجیتال آزمایشی QA» تبدیل و گارانتی نمونهٔ آن خالی شد؛ قیمت و SKU حفظ شدند. checkout بدون فیلد/picker نشانی، delivery=null، ارسال۰ با وجود سیاست ارسال ثابت غیرصفر و مبلغ۲۹۵۰۰۰۰۰ریال موفق بود. SM-2 ساخته شد؛ جزئیات مجوزدار مدیر و لغو آن، تغییر۱۵/۱/۱۴ به۱۵/۰/۱۵ و بازخوانی Cancelled در مشتری پذیرفته شد.
- فهرست خصوصی دو سفارش لغوشده و مبلغ دقیق در FA/EN، بدون اطلاعات تماس در summary، و audit تنظیم QA/ویرایش کالای QA/لغو مدیر موفق‌اند. هیچ پرداخت، تخصیص یا ارسال واقعی رخ نداد.

یک assertion ترکیبی اولیه به‌دلیل redaction ابزار از ورودی شماره نتیجهٔ منفی داشت؛ با خواندن مستقیم note و checked رضایت دوباره بررسی و اصلاح شد. شمارهٔ نرمال‌شده جداگانه در جزئیات سفارش اثبات شد؛ این خطای ابزار، خطای محصول ثبت نشده است. timeoutهای locator نیز فرمانِ موفق را دوباره اجرا نکردند؛ وضعیت تازه خوانده شد.

## حدود و محیط پایان اجرا

مالکیت دو مشتری، قطع پاسخ/replay و worker انقضا در این مرورگر اجرا نشدند؛ شواهد SQL قبلی حدود مستقل خود را دارند. درخواست viewport390 برای تب مشتری واقعاً1280 ماند؛ پذیرش موبایل مشتری اعلام نمی‌شود. بعداً پنل390 مشاهده و منوی آن استفاده شد، فقط همین دامنهٔ محدود پذیرفته است. reset درخواست شد اما اندازهٔ همان پنل390 ماند؛ cleanup تب/override هنوز نیازمند ابزار مرورگر فعال است.

در وقفهٔ عمدی اجرا، هر سه handle14666/30841/33682 ناپدید و listenerهای5181/3175/3105 و5080/3000/3173 بسته شدند؛ از timeout به‌تنهایی توقف استنتاج نشد. Docker هم متوقف بود؛ با مجوز قبلی D15/D18 از CLI رسمی بازگردانده و فقط SQL همین پروژه روشن شد. SQL اصلی و QA ONLINE، اصلی۱۷ و Redis چت exited دوباره تأیید شدند. `customer-operations-interruption.json` شاهد است. حدود۴۰GiB فضا آزاد بود.

**وضعیت تاریخی پیش از D22**: دیتابیس مشخص بالا و پوشهٔ credential/key خودش برای ادامهٔ CMS نگه داشته شده‌اند؛ پوشه0700 و فایل‌های credential0600 هستند. هیچ حذف wildcard یا volume مجاز نیست. پیش از شروع harness تازه، این run یا دقیقاً بازیابی یا دقیقاً جمع شود.

## CMS و اصلاح موبایل مرتبط

**ادامهٔ تاریخی پس از وقفه**: helper اکنون `--resume-run` نام دقیق مبدأ را می‌پذیرد؛ private folder/credential/key اصلی و رمز و MFA حساب تولیدشده را بررسی و بدون migrate/seed/ساخت حساب/role grant ادامه می‌دهد. خطای پیش از readiness دیتابیس/فایل قبلی را حفظ می‌کند؛ SIGTERM پس از readiness همان مبدأ را حذف می‌کند. پنج guard شامل رد main/مسیر/run ناموجود، رد اجرای هم‌زمان روی پورت مشغول و رد backup با API زنده موفق‌اند. SQL پس از خطای اجرای دوم هنوز۲ سفارش لغوشده،یک نشانی،CMS revision1 با draft جدید و published قبلی و main۱۷ داشت. همان QA زنده است: API/PID14700/session57174، admin/PID15420/session85613 و Next/PID15437/session34464. HTTP هر سه200 و خانه همچنان فاقد markerهای پیش‌نویس است؛ تصویر/مرورگر بعد از CSS هنوز پذیرفته نشده. `qa-resume-*` و `customer-operations-handoff.json` مرجع‌اند؛ وضعیت خاموشی بالاتر تاریخچه است. پیش از توقف/استفاده مالکیت دوباره بررسی شود.

تمرین مستقل SQL+key ring با۲۳ بررسی موفق و cleanup کپی کامل، و۴۳۱ واحد Linux/amd64 موفق نیز انجام شدند؛ [BACKUP-RESTORE](BACKUP-RESTORE.md) حدود را دارد. main runtime هنوز خاموش و ارتقای۱۸–۲۱ مستقل از انتشار CMS، گام آمادهٔ بعد است. هیچ رمز تولیدشده در logهای resume/restore یافت نشد؛ فایل خصوصی اصلی فقط برای ادامهٔ همین QA نگه داشته شده است.

هفت بررسی مستقل CMS با SQL موفق‌اند: منوی پنل390، انتخاب دو کالا/جابجایی ترتیب، جست‌وجوی SKU و حفظ انتخاب خارج نتیجه، ذخیره/بازخوانی پیش‌نویس و عدم تغییر عمومی تا انتشار. گزارش `cms-connected-ui.json` مرجع است. انتشار/بازگردانی ابتدا با رد خودکار مجوز متوقف شد؛ سپس پاسخ صریح D22 دریافت و این دو عملیات در همان QA با API/SQL/Next HTTP انجام شدند (جزئیات پایین).

فرم CMS در390 به‌علت padding تو‌در‌تو فقط163px برای picker باقی می‌گذاشت. CSS محدود به CMS/mobile فاصله‌ها را کم و pagination/checkbox را قابل جمع‌شدن کرد. typecheck و build مستقل `tmp/cms-mobile-admin-dist` موفق‌اند؛ بازبینی تصویری پس از اصلاح باقی است. فایل skill جدید مرورگر در مسیر اعلام‌شده و پس از جست‌وجوی cache پیدا نشد؛ ابزار قبلی CUA نیز دیگر در دسترس نیست. از مسیر جایگزین برای دورزدن رد انتشار استفاده نشد.

## پایان D22 و پاک‌سازی نهایی

مالک انتشار همین محتوای مصنوعی و بازگردانی را صریحاً مجاز کرد. ورود رمز/MFA با هویت خود QA، انتشار revision2، مشاهدهٔ سه marker در API و HTML واقعی Next، استقلال فارسی و بازگردانی revision3 به digest دقیق revision1، حذف markerها و دو audit موفق با۱۴ بررسی پذیرفته شدند؛ logout204. اسکریپت نخست restoreRevisionId را دو بار عدد JSON فرستاد و400 قطعی گرفت؛ پس از read تازه، رشتهٔ ده‌دهی ارسال و rollback204 شد. قاعدهٔ backend تغییر نکرد. cms-approved-publication.json شاهد است؛ این پذیرش API/HTTP است، بازبینی تصویری تازه نیست.

پس از اثبات مالکیت PID/cwd، فقط admin3175/Next3105/API5181 خود run متوقف شدند؛ harness خروج۰ و پیام حذف SQL/credential داد. query نهایی صفر SaymanTest، نبود همان مبدأ/پوشه، بسته‌شدن سه پورت، اصلی۱۷ و CMS اصلی هر زبان revision1 بدون marker QA و Redis چت exited را تأیید کرد. customer-operations-final-cleanup.json مرجع نهایی است؛ اعداد و اجراهای زندهٔ بالاتر تاریخی‌اند.
