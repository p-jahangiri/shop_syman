# جدول‌ها و عملیات پنل — D49

## بازطراحی D50

مالک ظاهر D49 را نپسندید. ظاهر مشترک دوباره طراحی شد: زمینهٔ خنثی، جداکنندهٔ ظریف، منوی «فیلتر ستون‌ها»، منوی «نمایش» برای ستون/تراکم، چیپ تنظیمات فعال، راهنمای محدودهٔ داده و footer کوتاه با بازهٔ ردیف و صفحه‌بندی. فیلترها دیگر کنار تک‌تک سرستون‌ها نیستند. منوی موبایل به پایین صفحه می‌آید؛ ردیف عملیات هنگام پیمایش افقی ثابت می‌ماند.

کالاها تب وضعیت، جست‌وجوی اصلی زنده و فیلتر دسته/برند جمع‌وجور، ستون برند، نشان واقعی منتخب/وضعیت و عملیات ویرایش سبک دارند؛ صفحه‌بندی محلی۱۰/۲۵/۵۰ردیف مستقل از دریافت cursor سرور است. آیکون کالا نماد عمومی است، تصویر واقعی کالا ادعا نمی‌شود. داده و فرمان‌ها از همان API اصلی‌اند. تغییر ظاهر مشترک به‌تنهایی پذیرش تک‌تک گردش‌ها یا تأیید مالک نیست. بخش‌های پایین، شرح تاریخی D49 هستند؛ شواهد جدید در STATUS/D50 ثبت می‌شوند.

هدف مالک: بررسی بخش‌به‌بخش کسب‌وکار، UI و جدول‌ها، راهنمای همان بخش، جست‌وجوی زنده و عملیات مدیریتی معتبر. TanStack موجود گسترش می‌یابد؛ نصب Material یا جایگزینی stack لازم نیست. فعال‌سازی فقط روی همان پنل3173/API5080/Sayman است.

## رفتار مشترک

- `AdminTable` روی markup موجود کار می‌کند و handlerها، کلید ردیف، کنترل نسخه، رسید و قفل فرمان نامشخص را نگه می‌دارد. جدول پیچیدهٔ دارای سلول ادغام‌شده با markup اصلی حفظ می‌شود تا جمع مالی یا ردیف‌ها حذف نشوند.
- عنوان ستون مرتب‌سازی صعودی/نزولی دارد؛ Shift مرتب‌سازی چندستونی را فعال می‌کند. تاریخ‌های تبدیل‌شده و مبلغ‌ها raw sort value دارند؛ ریال/شمارنده‌های بزرگ با Number مقایسه نمی‌شوند. اعداد فارسی و عربی و جداکنندهٔ هزارگان پشتیبانی می‌شوند.
- قیف ستون، مقادیر کوتاه و محدود را با انتخاب دقیق فیلتر می‌کند؛ «فعال» با «غیرفعال» یکی نیست. برای متن‌های بلند، ورودی جست‌وجوی ستون ارائه می‌شود.
- ستون‌های نمایان، نمای فشرده، شمار ردیف دریافت‌شده و بازنشانی محلی موجودند. جدول‌های کامل metadata صفحه‌بندی10/25/50 دارند؛ فهرست‌های سروری همان cursor/بخش‌بندی قبلی را حفظ می‌کنند. مجموع ساختگی برای کل داده نشان داده نمی‌شود.
- جست‌وجوی داخل جدول فقط دادهٔ دریافت‌شده را بررسی می‌کند. در کالا/انبار/کارکنان/مشتریان/شرایط خرید که جست‌وجوی اصلی سروری دارند، ورودی تکراری داخل جدول نشان داده نمی‌شود. فیلتر ستون و sort همچنان محدودهٔ همین صفحه دارند؛ مرتب‌سازی سراسری سرور پیاده نشده است.
- `AdminFilterForm` فقط فرم فیلتر خواندنی است: debounce350ms، حفظ IME، لغو timer در unmount، عدم ارسال فرم نامعتبر یا جداشده. فرم‌های ثبت/پرداخت/امنیتی خودکار submit نمی‌شوند. برخی گزارش‌ها با cutoff صریح همچنان دکمهٔ اعمال دارند.
- input/select/textarea/button و رمز از متن جست‌وجوی جدول استخراج نمی‌شوند. CSV یا دانلود خصوصی تازه، ذخیرهٔ اطلاعات جدول در browser storage و اعطای دسترسی تازه اضافه نشده است.
- راهنمای25بخش شامل purpose/steps/terms/محدودیت همان حوزه و توضیح ابزار جدول است. Field شناسه و نام و ارتباط hint پایدار می‌گیرد؛ نام‌های موجود RHF حفظ می‌شوند. Zod پیش از ساخت schema با jitless تنظیم می‌شود؛ CSP تضعیف نمی‌شود.

## بررسی کسب‌وکار به تفکیک بخش

| بخش | جریان/نمای مناسب | مرز کسب‌وکار و عملیات |
|---|---|---|
| نمای کلی | کارت آمار و میان‌بر | صفر/آمار از داده؛ مجوز هر حوزه مستقل |
| کالاها | جست‌وجوی سروری زنده، دسته/برند/وضعیت، جدول | افزودن/ویرایش معتبر؛ پنهان‌کردن از فرم، حذف قطعی بدون API ارائه نمی‌شود |
| کاتالوگ گوشی | فیلتر مدل و جدول ترکیب‌ها/منابع | مدل بازار موجودی سایمان نیست؛ فرمان/CSV و receipt حفظ |
| کالای کارکرده | انتخاب SKU و فرم گزارش همان واحد | نامعلوم صریح؛ گزارش پیشین سفارش تغییر نمی‌کند |
| موجودی | جدول SKU و مانده‌ها و گردش | اصلاح با دلیل؛ رزرو با کاهش فیزیکی آزاد نمی‌شود |
| دریافت تأمین | جدول task/دریافت/نگاشت | دریافت واقعی، تخصیص و تبدیل جدا؛ دادهٔ QA وارد نمی‌شود |
| دسته‌ها | جدول metadata و فرم | والد/ویژگی/فعال‌بودن با نسخه؛ وابستگی کالا حفظ |
| ویژگی‌ها | جدول metadata و فرم typed | نوع و گزینهٔ استفاده‌شده با اعتبارسنجی؛ مقدار آزاد جای typed data نیست |
| برندها | جدول metadata و فرم | نام/اسلاگ/فعال‌بودن؛ راهنمای نادرست «نام دو زبان» اصلاح شد |
| سفارش‌ها | جدول دریافت‌شده و جزئیات | ثبت با پرداخت متفاوت؛ لغو/ارسال فرمان معتبر، حذف تاریخچه ندارد |
| مشتریان | جست‌وجوی سروری و جدول/پرونده | اطلاعات تماس فقط جزئیات؛ سابقهٔ سفارش/تیکت با مجوز مستقل |
| درخواست تأمین | فهرست و جدول task/پیشنهاد | پذیرش مشتری، دریافت و تخصیص پیش‌نیاز تبدیل؛ idempotency محفوظ |
| تیکت‌ها | workspace گفت‌وگو و فهرست مکالمه | متن خصوصی و مالکیت حفظ؛ نمای مکالمه به جدول مصنوعی تبدیل نمی‌شود |
| دیدگاه‌ها | جدول به‌جای کارت‌های بلند | moderation/پاسخ به همان نسخه؛ نشان خریدار جعل نمی‌شود |
| روش‌های خرید و چک | جدول و فیلتر سروری زنده | فعال‌کردن روش provider را فعال نمی‌کند |
| پروندهٔ خرید چکی | workspace اختصاصی مدارک/تأیید | دسترسی و دانلود خصوصی واقعی؛ CRUD عمومی جای تصمیم مالی نیست |
| سررسید و گردش چک | جدول سفارش و گزارش سررسید | snapshot/cutoff و جمع صفحه حفظ؛ ارسال پس upfront و تأیید همهٔ چک‌ها |
| شرایط و مدارک چکی | ویرایش نسخه‌دار و تاریخچه | انتشار صریح؛ مدارک و schema قرارداد محفوظ |
| پرداخت/تطبیق | جدول و فیلتر وضعیت/سفارش | فقط تأیید سروری پرداخت؛ provider واقعی هنوز نامشخص |
| ارسال و مالیات | فرم policy نسخه‌دار | نرخ/هزینهٔ نامشخص خودکار صفر یا رایگان نمی‌شود |
| اتصال هلو | جدول نگاشت/ورود/تطبیق | نسخه و API واقعی نداریم؛ اتصال زنده خاموش می‌ماند |
| محتوا و تنظیمات | جدول صفحه/مقاله/redirect/اسناد/تاریخچه | پیش‌نویس با انتشار/بازگردانی فرق دارد؛ CAS/receipt حفظ |
| کارکنان | فیلتر زنده/جدول/فرم حساب | رمز اولیه→تغییر اجباری→MFA؛ تغییر خود/آخرین مدیر ممنوع |
| رویدادها | تاریخچهٔ خواندنی | سابقهٔ ممیزی قابل حذف/ویرایش عمومی نیست |
| امنیت | فرم Authenticator/بازیابی | credential به کاربر واگذار؛ هیچ حفاظت برای تست تضعیف نمی‌شود |

این جدول، پذیرش کامل تمام گردش‌های عملیاتی نیست. خواندن صفحه با ثبت سفارش/وصول/ارسال برابر نیست؛ شواهد دقیق و ادامهٔ هر بخش در STATUS ثبت می‌شوند. D16/D30 و سیاست‌های باز D21 حل‌شده فرض نشوند.

## شواهد

`admin-d49-table-source-audit.json`: اتصال45نمای جدول در34فایل؛ `admin-d49-guides-coverage.json`: راهنمای25بخش. تست‌های مدل جدول، مبالغ دقیق و تاریخ خام، حفظ handler و جمع ادغام‌شده، عدم جست‌وجوی password، debounce/IME/unmount و no-eval اضافه‌اند. رگرسیون CSV همچنان handler واقعی را با adapter ظاهری جدید بررسی می‌کند؛ assertion مالی/فرمان حذف نشده است.
