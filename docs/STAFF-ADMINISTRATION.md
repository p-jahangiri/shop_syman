# مدیریت کارکنان و دسترسی حساب

پذیرش جدید 2026-10-23: D20 توقف فضا را رفع کرد؛ **۱۲۹/۱۲۹ SQL واقعی** شامل آزمون‌های این برش موفق شدند. اعداد compile-only و توقف D19 متن زیر تاریخی‌اند؛ QA مرورگر متصل، main migration۱۸–۲۱ و Linux x64/بار هنوز جدا باقی‌اند. وضعیت جاری در [STATUS](STATUS.md) است.

وضعیت 2026-10-23: سرویس، پنل و آزمون‌های بدون SQL آماده‌اند. تغییر نقش/فعال‌سازی واقعی، رقابت SQL و انتشار اصلی هنوز پذیرفته نشده‌اند. این قابلیت ساخت حساب، دعوت، تأیید تماس یا بازیابی رمز را جایگزین نمی‌کند؛ providerهای D16 همچنان غیرفعال‌اند.

## گردش و API

| مسیر `/api/admin` | رفتار |
|---|---|
| GET `staff-role-catalog` | schemaVersion1/roles؛ شناسه، نام فارسی/انگلیسی و permissionهای نقش‌های شناخته‌شدهٔ سرور |
| GET `staff?query=...&active=all&role=all&cursor=...` | صفحهٔ۵۰، فیلتر نام/نام کاربری، نقش و فعالیت؛ cursor وابسته به همهٔ فیلترها |
| GET `staff/{id}` | جزئیات محدود همان کارمند و نسخهٔ جاری یا404 |
| GET `staff/{id}/history?cursor=...` |۵۰ رویداد دسترسی با Id نزولی و cursor مخصوص همان حساب |
| POST `staff-candidate` | identifier دقیقِ نام کاربری یا ایمیل در body؛ فقط metadata حساب موجود و قابلیت ورود، بدون مقدار تماس/رمز |
| POST `staff` | accountId/roles/version؛ افزودن حساب واجد شرایط، MFA اجباری و ابطال نشست‌های قبلی |
| PUT `staff/{id}` | roles/isActive/version صریح؛ جایگزینی نقش‌های مدیریت‌شده و وضعیت حساب، ابطال نشست‌ها |

خواندن‌ها staff.read و نوشتن/lookup staff.write دارند؛ هر دو به access کامل و نقش Administrator نیاز دارند. فقط Administrator در ماتریس فعلی این permissionها را دارد. ادعای permission به‌تنهایی یا mfa_pending کافی نیست. نقش‌ها از متادیتای سرور می‌آیند؛ تعریف دلخواه role/permission از مرورگر پذیرفته نمی‌شود.

افزودن از حساب موجود لازم است تا تأیید تماس یا رمز جعل نشود. حساب باید فعال، دارای نام کاربری و **رمز ورود موجود**، ایمیل یا موبایل تأییدشده، فاقد نقش کارکنان و فاقد بازیابی MFA ناتمام باشد. hasPassword فقط flag قابلیت است؛ hash برنمی‌گردد. حساب صرفاً OTP بدون رمز نمی‌تواند به ورود رمز/MFA پنل منتقل شود؛ خود کاربر باید از مسیر تأییدشده رمز تنظیم کند. دعوت/ثبت‌نام/تنظیم رمز وابسته به سرویس واقعی است و این صفحه هیچ رمز یا کلیدی نمی‌سازد. فعال‌کردن دوباره نیز تماس تأییدشده و رمز را بررسی می‌کند.

پس از اعطای نقش، ورود حساب از مسیر پنل و با MFA است؛ نشست مشتری قبلی هم باطل می‌شود. غیرفعال‌کردن، **کل حساب** را غیرفعال می‌کند و ورود فروشگاه و پنل را می‌بندد؛ داده/سفارش/کلید/رویداد حذف نمی‌شوند. فعال‌کردن دوباره عامل دوم موجود را دور نمی‌زند. حذف همهٔ نقش‌ها ممنوع است؛ برای قطع دسترسی از غیرفعال‌کردن استفاده می‌شود. تبدیل معکوس کارمند به مشتری، دعوت و بازیابی دستی بدون کد، در این برش پیاده نشده‌اند.

## داده، همزمانی و audit

فهرست فقط Id، نام کاربری/نمایشی، وضعیت، پرچم‌های MFA، زمان ایجاد، نقش‌های شناخته‌شده و ConcurrencyStamp به نام version دارد. **SecurityStamp، PasswordHash، شماره تماس، فیلد ایمیل، token و کلید/کد MFA در DTO نیستند**؛ خود نام کاربری می‌تواند ایمیل باشد. metadata حداکثر۵۱ حساب و سپس نقش‌های همان۵۰ شناسه را می‌خواند، بدون graph/token یا N+1. مشتری فاقد نقش کارکنان در فهرست نیست.

query حداکثر۱۲۰ نویسه/۸ واژه است. نرمال‌سازی ورودی فارسی، تبدیل ی/ک و ارقام در عبارت SQL و COLLATE ثابت Latin1_General_100_CI_AI برای مقایسهٔ نام آماده‌اند؛ SQL translation آزموده شده، اما رفتار واقعی Unicode و query plan/بار هنوز باید با SQL پذیرفته شوند. snapshot مشترک میان حساب/نقش یا صفحه‌ها وجود ندارد؛ تغییر همزمان می‌تواند نیازمند دریافت دوباره شود. ترتیب/seek از Id جاری است و سقف۴۵۰ نویسهٔ ASCII برای شناسه و۲۰۴۸ برای cursor دارد.

فرمان‌ها فقط داخل transaction Serializable فیلتر audit اصلی کار می‌کنند. ردیف نقش Administrator با UPDLOCK/HOLDLOCK تغییر عضویت را سری می‌کند؛ سپس actor و target قفل و دوباره load می‌شوند. stamp، فعالیت، lockout، MFA کامل، تماس تأییدشده و نقش جاری actor دوباره بررسی می‌شوند. کنترل middleware به‌تنهایی مرجع نوشتن نیست.

تغییر دسترسی خود actor، حتی با تفاوت بزرگی حروف Id، ممنوع است. همراه شمارش مدیر فعال و بررسی دوبارهٔ actor زیر قفل، دو مدیر نمی‌توانند با درخواست همزمان یکدیگر را غیرفعال کنند و آخرین دسترسی مدیریتی را از بین ببرند. roles نامعتبر/تکراری/خالی، isActive حذف‌شده و version نامعتبر پیش از SQL/audit رد می‌شوند؛ نسخهٔ قدیمی409 می‌دهد. نسخهٔ هدف زیر قفل بررسی می‌شود، بنابراین replay نسخهٔ مصرف‌شده دوباره اعمال نمی‌شود.

Roleهای شناخته‌شدهٔ قبلی حذف/افزوده و roleهای خارج از این ماتریس دست‌نخورده می‌مانند؛ RequireMfa اجباری و SecurityStamp عوض می‌شود، همهٔ refresh sessionهای قبلی revoke می‌شوند. رمز، کلید Authenticator و وضعیت بازیابی هدف تغییر نمی‌کنند. refresh منسوخ، stamp تازه را دوباره نمی‌چرخاند؛ گیت آن در MFA-RECOVERY ثبت شده است. refresh همزمان می‌تواند deadlock/409 بدهد؛ پذیرش این رقابت هنوز باقی است و تست مجزا نوشته شده است.

علاوه بر audit اصلی درخواست، رویدادهای `STAFF_GRANTED`، `STAFF_ROLE_ADDED:{role}`، `STAFF_ROLE_REMOVED:{role}`، `STAFF_ENABLED`/`STAFF_DISABLED` و `STAFF_SESSIONS_REVOKED` با Resource=/staff/{targetId}، actor/trace/time ثبت می‌شوند. نقش قدیمی/تازه از deltaها قابل پیگیری است؛ مقدار تماس، identifier جست‌وجو، رمز، hash یا کلید در آن‌ها نیست. شکست audit اصلی کل نقش/وضعیت/stamp/نشست و رویدادهای دامنه را rollback می‌کند. دادهٔ قدیمیِ پیش از این قابلیت رویداد دسترسی ساختگی نمی‌گیرد.

Identity مالک همهٔ داده‌هاست؛ سرویس به DbContext ماژول دیگر دسترسی ندارد. audit اصلی composition root همان هماهنگی قبلی را دارد. جدول/ستون تازه‌ای لازم نیست؛ Source همچنان۱۹ و اصلی آخرین‌بار۱۷ migration داشت، Sales۱۸ و Identity۱۹ اعمال نشده‌اند. هیچ SQL/Docker تازه در این برش اجرا نشد.

## پنل و شاهد محدود

صفحهٔ lazy کارکنان، جست‌وجو/فیلتر/قبلی/بعدی، پرچم‌های MFA، جزئیات تازه و تاریخچهٔ صفحه‌بندی‌شده دارد. حساب خود مدیر فقط خواندنی است؛ گیت سرور هم مستقل اعمال می‌شود. draft هنگام focus/reconnect عوض نمی‌شود. دریافت تازهٔ صریح، حتی با version یکسان، draft را کنار می‌گذارد. نقش ناشناخته از payload حذف نمی‌شود؛ تا دریافت تعریف معتبر، ذخیره بسته می‌ماند.

lookup با تغییر حساب، انتخاب نقش قبلی را پاک می‌کند. حساب تأییدنشده/بدون رمز/غیرفعال/کارمند موجود قابل افزودن نیست. افزودن یا تغییر نقش فقط با اقدام صریح روی حساب و نقش‌های نمایش‌داده‌شده انجام می‌شود. ارسال خودکار/تکرار خودکار mutation وجود ندارد؛ در قطع پاسخ، UI احتمال ثبت و لزوم دریافت دوباره را بیان می‌کند. تعارض و خطای transaction پیام روشن دارند و draft حفظ می‌شود. رمز، token و کد MFA در URL/storage/PWA قرار نمی‌گیرند. فیلترهای فهرست در querystring درخواست GET هستند؛ identifier دقیقِ افزودن در body POST ارسال و در localStorage یا PWA ذخیره نمی‌شود.

- **۳۳۵ واحد بک‌اند موفق**،۲۴ تازه برای فیلتر/cursor/ورودی، projection SQL بدون secret، متادیتای نقش، policy/نوع token، validation پیش از audit و قرارداد native/flag بدون رمز. مثبت‌های native از reader مصنوعی test assembly هستند؛ پذیرش SQL یا MFA واقعی نیستند.
- **۲۶ contract پنل موفق**،۶ تازه برای schema/فیلتر/پاسخ خصوصی/شناسه/نسخه، انتخاب نقش و گیت بدون رمز و تاریخچهٔ bigint. شناسهٔ نامعتبر پیش از BigInt رد می‌شود؛ دادهٔ ورودی در پیام خطای parser نمایش داده نمی‌شود. TypeScript و build ایزولهٔ tmp/staff-admin-dist موفق‌اند؛ entry۳۲۵٫۲۸ + schemas preload۸۵٫۶۳، جمع اولیه۴۱۰٫۹۱/gzip۱۲۸٫۱۵kB و staff lazy۱۶٫۶۶/gzip۵٫۲۹kB؛ هشدار۵۰۰kB نیست، threshold عوض نشد و Core Web Vitals اندازه‌گیری نشده‌اند. dist اصلی تغییر نکرد.
- **۱۴ wire واقعی test host→TypeScript** با `verify-admin-wire.mts artifacts/checks/admin-wire-staff --mfa-recovery --staff`؛ چهار پاسخ تازه page/detail/roles/history، Id بالاتر از safe integer و nextCursor=null صریح را تأیید کردند. flags اختیاری‌اند؛ فرمان قدیمی بدون flag همان۷ بررسی را دارد. هیچ هویت واقعی از این capture ساخته نمی‌شود.
- **۲۴ QA محدود رابط** با fixture صریح:۵۰/۵۰/۱ و تاریخچه۵۰/۵۰/۲۱، خودحفاظتی رابط، discard نسخهٔ یکسان، خطا503/409، حساب تأییدنشده/بدون رمز/غیرفعال/کارمند موجود، عدم انتقال انتخاب قبلی، جست‌وجوی خارج صفحه و فیلتر ترکیبی، پاسخ خصوصی/شناسهٔ غلط و retry؛ فهرست/فرم‌ها در۳۹۰×۸۴۴ بدون overflow. CSS نهایی نام و نام کاربری را جدا نشان می‌دهد. console error/warning گزارش‌شده صفر؛ **هیچ اعطای دسترسی، تغییر حساب، ورود یا SQL واقعی در fixture موفق نشده است**.
- **۶ SQL تازه فقط compile شده‌اند**: اعطای نقش با حساب معتبر و رد پیش‌نیازهای ناقص، ابطال authority و نسخهٔ قدیمی، دو مدیر همزمان/Id خود با تفاوت حروف، rollback audit، صفحات۱۰۱ کارمند/۱۲۱ رویداد و Unicode، refresh همزمان با غیرفعال‌کردن. discovery بدون اجرا **۸۴ مورد** دارد؛ شاهد قبلی۵۹ و **۲۵ مورد تازه هنوز اجرا نشده‌اند**.

گزارش staff-source.json، logهای staff-*، captureهای admin-wire-staff و تصاویر sayman-staff-* در artifacts/checks مرجع‌اند. script مستقل `serve-staff-layout.py --explicit-readonly-fixture` به capture نقش‌ها نیاز دارد؛ هیچ route آن به API اصلی نمی‌رود و Cookie/Authorization قبل از fixture حذف می‌شوند. سه lifecycle موقت، تب‌های۲۲/۲۳/۲۴ و viewport پاک‌سازی شده‌اند؛ جزئیات PID/درخواست‌ها در گزارش‌اند. اصل CORS/MFA/Policy در این fixture پذیرفته نشده است.

پس از اعلام پایان آزادسازی فضا، SQL۸۴ و مرورگر واقعی با حساب/کلید موقت، ورود و نقش‌های مختلف، race/timeout و سپس migration۱۸/۱۹، build/update و smoke اصلی انجام شوند. دعوت/ساخت حساب و providerها، MFA/backup واقعی، Linux x64، plan/بار و همهٔ فازهای PLAN بازند؛ این برش پایان Identity یا پروژه نیست.
