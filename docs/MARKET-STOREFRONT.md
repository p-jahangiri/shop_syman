# رابط عمومی کاتالوگ بازار

وضعیت جدید 2026-10-25: فیلتر دسته/برند با شمارندهٔ کل مدل‌های مجاز SQL و فیلتر برند پنل روی اصلی۴۲ منتشر است؛ [MARKET-FACETS](MARKET-FACETS.md) و STATUS مرجع این تکمیل‌اند. توضیح‌های زیر سابقهٔ برش اولیه‌اند؛ نبود dropdown/facet دسته و برند در آن مرحله، محدودیت جاری نیست. facet ویژگی‌های تایپ‌دار هنوز باز است.

برش خواندنی 2026-10-23: سورس فروشگاه دارای مسیرهای `/fa/market` و `/en/market` و جزئیات `/[locale]/market/[listingId]` است. این برش سبد درخواست تأمین، پیشنهاد مدیر، قبول مشتری، تبدیل به SKU یا MARKET-02 کامل نیست. دادهٔ منبع فقط از API واقعی بازار می‌آید؛ در حالت preview مدل یا قیمت ساختگی تولید نمی‌شود و سرویسِ پیکربندی‌نشده صریحاً unavailable است.

## رفتار و مرزها

- مدل بازار، DTO مستقل از Product قابل فروش است. decoder در هر سطح فیلد اضافه، SKU، موجودی، روش خرید و مبلغ عددی را رد می‌کند. مشخصات، تصاویر و نام دسته/ویژگی از Catalog و متادیتای فعلی فروشگاه می‌آیند. مدل به product registry، سبد خرید، quote یا checkout تزریق نمی‌شود.
- فهرست، جست‌وجوی حداکثر۱۲۰نویسه/۸واژه، دسته، برند و صفحهٔ۱–۱۰۰۰۰/اندازهٔ۱–۲۴ دارد. دسته‌ها از متادیتای واقعی می‌آیند. نام برند هر کارت به فیلتر همان برند پیوند دارد و فیلتر فعال قابل حذف است. API بازار هنوز endpoint فهرست کامل برند/ویژگی‌های facet ندارد؛ dropdown با برندهای صفحه یا برندهای فروشگاهِ دارای پیشنهاد فروش ساخته نشده است، چون برای مدلِ فقط بازار ناقص می‌بود. فیلتر ویژگی پویا و فهرست کامل برندها همچنان کار backend مستقل‌اند.
- مبلغ مثبتِ ریال رشته‌ای با BigInt فقط در مرز نمایش به تومان تبدیل می‌شود. برچسب «قیمت مرجع منبع / قابل پرداخت نیست»، نام منبع، زمان مشاهده، اعتبار، نیازمند استعلام/گزارش موجود/گزارش ناموجود/منقضی و نمونهٔ توسعه آشکارند. اعتبار روی صفحه هر۱۵ثانیه نیز بررسی می‌شود تا پایان مهلت، قیمت/گزارش را جاری جلوه ندهد. دادهٔ تازه به‌طور خودکار از provider درخواست نمی‌شود.
- جزئیات، گالری با انتخاب‌گر قابل دسترسی، ویژگی‌های نمایشی مطابق قواعد دسته، شرح مدل و ارجاع HTTPS بدون query/credential به منبع را دارد. زمان‌ها به وقت تهران و در فارسی با تقویم/ارقام محلی نمایش داده می‌شوند. پیوند برند و تغییر زبان همان شناسهٔ listing را حفظ می‌کنند.
- بخش درخواست تأمین فعلاً دکمهٔ غیرفعال و توضیح روشن دارد. هیچ ثبت موفق، رزرو، موجودی یا خرید فرضی ایجاد نمی‌کند؛ پس از ساخت قرارداد/SQL واقعی تأمین باید به گردش اصلی متصل شود.
- عنوان/راهنمای فنی رابط FA/EN در `market-copy.ts` است؛ نام/شرح/ویژگی/تصویر/منبع دادهٔ API است. ناوبری اصلی همچنان CMS است. `Cms.Content.ValidatePath` از قبل مسیر داخلی امن را می‌پذیرد؛ `/market` به تغییر allowlist نیاز ندارد. این برش هیچ CMS اصلی را منتشر یا seed نکرده و لینک منوی بازار باید جدا با انتشار نسخه‌دار CMS اضافه شود.
- تمام صفحات بازار فعلاً `noindex` هستند؛ هیچ Offer/قیمت قابل پرداخت در JSON-LD یا sitemap فروشگاه ساخته نشده است. سیاست نهایی SEO بازار، facetها و صفحات منابع بعداً جدا پذیرفته می‌شوند.

## API/BFF

`market-http.ts` منطق قابل آزمون خواندن و proxy را نگه می‌دارد؛ `market-server.ts` فقط environment سرور را به آن می‌دهد. Next مسیرهای زیر را ارائه می‌کند:

| مسیر | رفتار |
|---|---|
| `POST /api/market/{fa|en}/search` | ورودی strict؛ فقط query/categoryId/brandId/page/pageSize |
| `GET /api/market/{fa|en}/{listingId}` | جزئیات همان listing عمومی؛ تطبیق شناسهٔ پاسخ |

ورودی body حداکثر۴KiB با JSON MIME، خروجی upstream حداکثر۲MiB با UTF-8 معتبر/JSON MIME، deadline۸ثانیه، لغو اتصال و no-store دارد. پارامتر URL ناشناخته/تکراری در صفحه و query اضافی در BFF رد می‌شوند. پاسخ به locale/page/size/category/brand درخواست مقید است. upstream فقط Accept و Content-Type خود سرویس را می‌گیرد؛ cookie، bearer، Host، Origin و اختیار مدیریت کاربر forward نمی‌شوند. Origin ارسالی باید دقیقاً با origin عمومیِ تنظیم‌شده یا origin همین درخواست برابر باشد. redirect ممنوع و خطای داخلی upstream به متن ثابت و وضعیت محدود تبدیل می‌شود. پاسخ همیشه no-store/nosniff/noindex است. Service Worker هیچ API یا HTML بازار/قیمت مرجع را وارد cache آفلاین نمی‌کند؛ تصاویر عمومیِ تأییدشده همان سیاست قبلی را دارند.

## شواهد جاری

- `market-storefront-targeted.log`: یازده تست decoder/proxy بازار موفق؛ پول فراتر از دقت Number، زمان هفت‌رقمی .NET، فیلد اضافه، دادهٔ غیرقابل فروش، ادعای منبع ناسازگار، page/query bounds، origin/authority، MIME/UTF-8/stream limit و خطای سرویس پوشش دارند.
- `market-storefront-all-tests.log`: کل۱۳۲ تست فروشگاه با صفر fail/skip موفق‌اند؛۱۲۰ قبلی+۱۱ بازار+۱ منع cache دادهٔ بازار. `market-storefront-typecheck.log`: `tsc --noEmit` موفق، بدون اجرای typegen در `.next` اصلی.
- `market-storefront-live-wire.json`: پانزده assertion واقعی خواندنی روی API5080/SQL اصلی؛ هر دو زبان،۳ مدل صریح نمونه، جزئیات دقیق همان مدل‌ها، unknown/available/stale، دسته+برند، صفحه۲ با اندازه۱ و نتیجهٔ خالی پذیرفته شدند. هیچ دادهٔ اصلی یا حسابی تغییر نکرد.
- `market-storefront-final-build.log`: build نهایی با helper موجود در `.next-qa` موفق؛ مسیرهای browse/detail/BFF همگی dynamic ثبت شده‌اند. build نخست پس از تغییر کوچکِ guard صفحه‌بندی در حین compile، فقط با SIGTERM به helper شناسایی‌شدهٔ خودش لغو۱۳۰ شد تا artifact از سورس نهایی باشد؛ شکست محصول/کامپایل ادعا نمی‌شود. helper فایل‌های tsconfig/next-env تولیدشده را برگرداند. `.next` اصلی/Next3000/پنل3173 در این برش restart یا بازنویسی نشده‌اند.
- `market-storefront-isolated-http.json`:۲۸ بررسی واقعی روی standalone ایزولهٔ loopback3107 متصل به API5080/SQL پذیرفته شد: HTML و BFF دو زبان، جزئیات/منبع/انقضا/غیرقابل پرداخت، مشخصات، درخواست تأمین غیرفعال، دسته/برند/صفحه، خالی/URL تکراری و400/403/404. HTML و BFF هر دو no-store/noindex بودند. مشاهدهٔ نخست harness به علت تبدیل headerها به dict حساس به بزرگی حروف متوقف شد؛ بازخوانی با HTTPMessage حساس‌نبودن استاندارد HTTP را رعایت و همه را پذیرفت. شاهد مرورگر نیست.

- `market-storefront-ui-acceptance.json`: پانزده assertion مرورگر واقعی CUA در تب پنهان خود QA روی `sayman-market.localhost:3107` پذیرفته شد؛ هیچ تب/حساب/MFA مالک بازخوانی نشد. دسکتاپ فارسی۱۲۸۰×۷۲۰ با عرض سند۱۲۶۵، موبایل فارسی/انگلیسی۳۹۰×۸۴۴ با عرض سند۳۷۵، بدون overflow افقی بودند. سه حالت منبع، نمونه/مرجع غیرقابل پرداخت، کلیک برند، حفظ برند در تغییر زبان، حفظ listing در تغییر زبان جزئیات، مشخصات ترجمه‌شده، جست‌وجو+دستهٔ واقعی/خالی/پاک‌کردن، حرکت Tab از جست‌وجو به دسته و دکمهٔ درخواست غیرفعال پذیرفته شدند. console ثبت‌شده صفر error/warn بود. تصاویر viewport در `artifacts/checks/market-storefront-{desktop-fa,mobile-fa,mobile-fa-cards,mobile-en,mobile-en-detail,mobile-fa-detail}.jpg` هستند؛ تصویر full-page در RTL برای پذیرش استفاده نشد.

در اجرای ایزوله، پوستهٔ مشترک هشدار اتصال سبد را نمایش می‌داد؛ این هشدار پنهان نشد و اجازهٔ origin یا احراز هویت برای رفع مصنوعی آن تغییر نکرد. پذیرش مرورگر این سند، بازارِ خواندنی است و اتصال سبد/حساب در origin QA تازه را ثابت نمی‌کند. unavailable از قرارداد/proxy آزموده شده، ولی قطع واقعی API هنگام حضور در مرورگر و retry error boundary هنوز جدا پذیرفته نشده‌اند. آزمون کامل keyboard/screen reader، reduced motion، CWV و دستگاه واقعی نیز ادعا نمی‌شود.

پس از پذیرش مستقل، همین artifact در tmp/storefront-runtime-market-11cfad3d24a74462a5965c08cc9aa8d2 کپی و روی3000 با API mode اجرا شد؛ PID18253/session49713.۱۴ smoke دو زبان/بازار/جزئیات/BFF/پنل موفق‌اند؛ market-storefront-main-smoke.json و tmp/storefront-runtime-current.json شاهدند. .next قبلی برای بازگشت محفوظ است؛ منوی CMS هنوز اضافه نشده. SQL بازار/پنل CSV قبلاً جدا پذیرفته‌اند و شاهد این سند پذیرش کل جریان تأمین یا provider نیست. پس از پذیرش، tab خود QA بسته و viewport override reset شد؛ standalone3107 با بررسی PID10556/cwd ایزوله و SIGTERM متوقف شد (session31631 exit143؛ listener3107 بسته). هیچ دیتابیس یا حساب QA برای این برش ساخته نشد؛ فقط خواندن عمومی SQL اصلی انجام شد.

## تحویل artifact و انتشار بعدی

سورس فقط در `apps/storefront` و همین سند تغییر کرده؛ schema/API/admin/CMS اصلی عوض نشده‌اند. artifact پذیرفته در `apps/storefront/.next-qa/standalone/apps/storefront/server.js` است و `public/` و `.next-qa/static/` لازم کنار آن کپی شده‌اند. helper config نهایی همان `distDir=.next-qa` را در standalone نگه می‌دارد؛ انتقال artifact به معنی تغییر نام این پوشه به `.next` نیست.

برای انتشار محلی بعدی، کل `.next-qa/standalone` را در یک مسیر مستقل و تازهٔ `tmp` نگه دارید تا build ایزولهٔ آینده فایل‌های runtime را عوض نکند. همان `apps/storefront/server.js` منتقل‌شده را با environment واقعیِ API/`SHOP_DATA_MODE=api`، `SHOP_PUBLIC_URL` صحیح origin اصلی و پورت اصلی اجرا کنید؛ preview روشن نشود. پیش از جایگزینی، PID/cwd فعلی Next3000 و مسیر بازگشت آن را تأیید کنید؛ فقط همان سرویس متعلق به پروژه متوقف شود. پس از سلامت و smoke دو زبان/بازار/BFF/PWA روی origin اصلی، منوی `/market` را با نسخه و audit CMS اضافه کنید. این سند اجازهٔ دست‌زدن به برنامه‌های دیگر یا providerهای غیرفعال نمی‌دهد؛ انتشار واقعی Linux/Docker، بکاپ/rollback و پذیرش کل پروژه همچنان معیار مستقل دارند.
