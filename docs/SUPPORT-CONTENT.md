# محتوای قابل مدیریت پشتیبانی

در اصلی محلی۵۱ به‌صورت انتشار فقط کد پذیرفته شده است. هدف: حذف FAQ ثابت از حالت API فروشگاه، ویرایش مستقل فارسی و انگلیسی در CMS موجود، انتشار/بازگردانی واقعی، و دسترسی آسان به تیکت از حساب مشتری. این برش، سیاست تجاری یا اتصال پیامک/چت زنده ایجاد نمی‌کند.

## قرارداد پیاده‌شده

سند `support` در همان `cms.Documents/Revisions` قرار می‌گیرد؛ migration لازم نیست. محتوای هر زبان شامل schemaVersion1، برچسب نمونهٔ توسعه، متن بالای عنوان، عنوان/شرح صفحه، متن دکمهٔ تیکت، عنوان/شرح FAQ و حداکثر۳۰ پرسش است. هر پرسش ID پایدار N-UUID، متن سؤال/پاسخ ساده و enabled مستقل دارد. ترتیب آرایه، ترتیب نمایش است. متن سؤال حداکثر۲۴۰ و پاسخ حداکثر۴۰۰۰ نویسه؛ کل سند حداکثر۱۰۰KiB. HTML اجرا نمی‌شود؛ فیلد یا شناسهٔ تکراری/ناشناخته و متن نامعتبر رد می‌شوند.

تنها نسخهٔ منتشرشده خوانده می‌شود. نبود سند یا پیش‌نویس منتشرنشده، `content:null,revision:0` می‌دهد؛ پیش‌نویس و سؤال غیرفعال بیرون نمی‌روند. زبان دیگر جایگزین زبان درخواست‌شده نمی‌شود. پاسخ عمومی، locale و revision صریح و قرارداد سخت‌گیر دارد؛ خرابی داده، خطای مشخص و بدون fallback ساختگی است. سند نمونه فقط در Development مجاز به نمایش است و در UI همان برچسب را دارد؛ دادهٔ نمونه در Production به‌عنوان محتوای واقعی ارائه نمی‌شود.

پنل از cms.read/write و MFA موجود استفاده می‌کند. ایجاد سند مفقود با version=null، ویرایش با نسخهٔ دقیق، و انتشار/بازگردانی با root Serializable و audit فعلی است. ذخیره به‌تنهایی انتشار نیست. ابتدا گردش SQL و مرورگر QA مستقل پذیرفته شود؛ دادهٔ QA به اصلی کپی نمی‌شود. شرایط ارسال/مالیات/چک/گارانتی/مرجوعی از متن نمونه به تنظیمات فروش تبدیل نمی‌شوند. اگر نمونهٔ محلی لازم شد، ابزار Development صریح با dry-run پیش‌فرض و حفظ سند موجود/برچسب نمونه لازم است؛ انتشار یا بازنویسی خودکار سند مالک ممنوع است.

پیش‌نمایش طراحی می‌تواند راهنمای نمونهٔ صریح خودش را داشته باشد؛ API mode فقط متن منتشرشده را می‌خواند. اگر FAQ منتشر نشده، بخش خالی نمایش داده نشود و مسیر تیکت همچنان در دسترس باشد. در خطای موقت CMS، تیکت از دسترس خارج نشود. عنوان و پیام‌ها در رابط کارمند باید خطاب به پشتیبان باشند. لینک تیکت در حساب مشتری با زبان جاری اضافه می‌شود.

## پذیرش لازم

اعتبارسنجی متن/شناسه/فیلدها، جداسازی draft/published/locale/demo، عدم نشت سؤال disabled، مجوزها/MFA، رقابت نسخه‌ها، rollback audit، restore نسخهٔ متعلق به همان سند/زبان، wire واقعی با decoder تولیدی، پنل تا فروشگاه FA/EN با انتشار/بازگردانی و حفظ محتوا، نبود اثر روی سایر ماژول‌ها، cleanup و backup/حفظ اصلی. مدل‌های CMS دیگر، منوی site3، روش‌های ورود auth1، تیکت و مبالغ قبلی حفظ شوند. بدون اتصال واقعی، SMS/Email/SignalR یا کل پروژه کامل معرفی نشود.


## شواهد پذیرش 2026-10-26

۹۰۷ واحد/۶۳۹ SQL واقعی/۳۵۸ فروشگاه/۲۱۲ پنل و build/typecheck،۹ پاسخ SQL با decoder تولیدی و۲۵ پاسخ/۸ ورودی مرورگر پذیرفته‌اند. ContentManager واقعی با MFA در GUID موقت و مشتری مستقل استفاده شدند؛ هیچ حساب مالک استفاده نشد. draft مخفی، دو زبان مستقل، ترتیب و disabled، HTML plain، انتشار با پاسخ204 قطع‌شده و retry همان نسخه409، ویرایش منتشرنشده، preview تاریخی و restore فارسی revision3 و حفظ EN، حساب→تیکت بررسی شدند. از۱۴۲ جدول،۱۳۷ جدول دیگر عیناً برابر بود؛۷ audit مربوط به۳ save و۴ publish موفق و تنها۲ سند/۴ revision جدید ثبت شد. محیط QA و کلیدهایش پاک شدند.

`support-content51-source-acceptance.json`، `support-content-final-sql-wire/acceptance.json`، `support-content-browser-wire/acceptance.json` و تصاویر browser شواهدند. بستهٔ immutable شامل۱۳ DLL یکسان با unit/SQL/harness است. backup تازه و انتشار بدون migration/seed، برابری همه۱۴۲ جدول/schema/view پیش و پس، و۹۴۴ HTTP با حفظ assetهای قبلی موفق‌اند؛ `support-content51-main-release.json`. اصلی هنوز support content ندارد و FAQ خالی پنهان است؛ نمونهٔ QA کپی نشد. پذیرش desktop۱۲۸۰ است؛ mobile، چت زنده، فایل، SMS/email و کل SUPPORT-01 جدا باقی‌اند.
