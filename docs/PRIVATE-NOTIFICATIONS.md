# اعلان خصوصی داخل حساب

در اصلی محلی۵۲ پذیرفته و منتشر شده است. هدف نخست SUPPORT-01: پاسخ یا بستن/بازگشایی تیکت توسط پشتیبان، اعلان دائمی برای صاحب همان تیکت ایجاد کند. اعلان داخل فروشگاه است؛ ارسال ایمیل/پیامک/Push یا SignalR در این برش فعال نمی‌شود و D16 باز می‌ماند.

## مرز داده و transaction

ماژول Notifications جدول اختصاصی در schema notifications دارد. اطلاعات اعلان فقط شناسهٔ مالک، شناسهٔ تیکت، نوع محدود (پاسخ، بستن، بازگشایی)، زمان UTC و زمان خوانده‌شدن است؛ متن/عنوان خصوصی پیام، نام/تماس مشتری، کلید یا URL دلخواه کپی نمی‌شود. UI متن نوع را در زبان جاری نمایش می‌دهد و لینک داخلی تیکت را از ID معتبر می‌سازد. owner یا کلید رویداد داخلی در DTO نیست.

Support فقط قرارداد SharedKernel را فراخوانی می‌کند. فرمان کارمند، ثبت پیام/وضعیت، اعلان و audit در همان transaction Serializable ریشه هستند؛ شکست هرکدام همه را برمی‌گرداند. event identity پایدار و unique مالک+منبع از اعلان تکراری جلوگیری می‌کند؛ replay رسید فرمان Support کار تازه‌ای انجام نمی‌دهد. فرمان‌های خود مشتری اعلان برای خودش نمی‌سازند. تاریخچهٔ اعلان حذف/ویرایش نمی‌شود؛ تنها انتقال یک‌طرفهٔ ReadAt از null به زمان سرور مجاز است.

فهرست مالک با seek۵۰تایی، فیلتر unread و cursor مقید به مالک/فیلتر است؛ شمارندهٔ unread مستقل و صریح است، snapshot مشترک با فهرست ادعا نمی‌شود. sequence/count از SQL bigint به رشتهٔ ده‌دهی می‌آیند. `PUT .../{id}/read` انتقال یکنواخت و idempotent است؛ تکرار ReadAt اولیه را عوض نمی‌کند. مالک از JWT معتبر گرفته می‌شود و ورودی owner پذیرفته نیست. نشانهٔ خوانده‌شدن فقط متعلق به همان مشتری است؛ مجوز کلی پشتیبانی دسترسی به اعلان شخصی دیگران نمی‌دهد.

## رابط و پذیرش لازم

صفحهٔ خصوصی FA/EN از حساب، فهرست/فیلتر/تازه‌سازی/صفحهٔ بعد/وضعیت خالی/خطا و لینک تیکت، خوانده‌شدن صریح و شمارنده لازم است. پاسخ مالی یا محتوای تیکت به cache PWA نمی‌رود؛ BFF bearer بدون cookie و پاسخ no-store/noindex است. این برش polling/SignalR زنده نیست؛ کاربر تازه‌سازی می‌کند.

آزمون SQL واقعی باید مالکیت/guest/role/origin/extra fields، reply/close/reopen، self-action بدون اعلان، replay و race، rollback audit و notification و حفاظت تاریخچه، صفحه‌بندی و ReadAt یکنواخت را ثابت کند. wire تولیدی/مرورگر واقعی، حفظ سایر جدول‌ها، cleanup QA، migration additive بدون دادهٔ جعلی، backup و انتشار محلی بعد از پذیرش لازم‌اند. دادهٔ اصلی۵۱ تا آن زمان حفظ می‌شود. mobile/بار و سایر انواع اعلان/پرداخت/SMS کامل معرفی نشوند.
