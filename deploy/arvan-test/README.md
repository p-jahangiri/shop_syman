# نسخهٔ آزمایشی Docker سایمان روی آروان

این Compose برای اجرای Development روی سرور اختصاص‌یافتهٔ آزمایش است. API و SQL فقط در شبکهٔ Docker هستند. فروشگاه و پنل روی loopback میزبان به‌ترتیب ۱۳۰۰۰ و ۱۳۱۷۳ در دسترس‌اند. پروفایل `edge` پس از صدور گواهی عمومی فعال می‌شود و فقط IP آزمایشگر به رابط‌ها دسترسی دارد.

## آماده‌سازی

بستهٔ سورس را با `deploy/package-production.py` صادر کنید. برای ارسال به Linux از tar بدون AppleDouble استفاده کنید و SHA-256 آرشیو را در مقصد بررسی کنید. تصاویر API، فروشگاه و پنل را برای `linux/amd64` بسازید. در build پنل، `VITE_STOREFRONT_URL` را با مسیر دسترسی واقعی هماهنگ کنید. برای تونل از `http://127.0.0.1:13000` استفاده کنید.

برای Compose از فایل خصوصی `deploy.env` شامل نام تصویرها و متغیرهای `SAYMAN_SHARED`، `SHOP_ORIGIN`، `ADMIN_ORIGIN`، `SHOP_DOMAIN`، `ADMIN_DOMAIN` و `TESTER_IP` استفاده کنید. در پوشهٔ مشترک میزبان:

- `sql.env` رمز تازهٔ `MSSQL_SA_PASSWORD` را دارد. حجم `sql-data` پایدار است.
- `runtime.env` رشتهٔ اتصال حساب محدود دیتابیس، `Auth__SigningKey` و `DataProtection__CertificatePassword` را دارد. هر رمز و کلید جداگانه تولید می‌شود.
- `identity-keys` و گواهی مستقل `identity.pfx` برای UID برنامهٔ API خواندنی‌اند. فایل گواهی و کلیدهای برنامه با TLS درگاه متفاوت‌اند.
- `development.json` از `backend/Seed/development.json` می‌آید.

بعد از سلامت SQL، دیتابیس Sayman و حساب runtime محدود به خواندن و نوشتن همان دیتابیس را بسازید. بکاپ اولیه را با `BACKUP … WITH COPY_ONLY, CHECKSUM` و `RESTORE VERIFYONLY … WITH CHECKSUM` بگیرید. برای نصب نخست، `--seed-dev` را یک‌بار در کانتینر API با اتصال موقت migration و `Bootstrap__AdminPassword` تازه اجرا کنید. مقادیر موقت در محیط کانتینر دائم قرار نمی‌گیرند. بعد از بکاپ دادهٔ نمونه، Compose را بالا بیاورید و سلامت API، صفحهٔ فروشگاه و پنل را بررسی کنید.

## دسترسی از طریق تونل

```sh
ssh -N -o ExitOnForwardFailure=yes \
  -L 127.0.0.1:13000:127.0.0.1:13000 \
  -L 127.0.0.1:13173:127.0.0.1:13173 root@94.101.186.45
```

در زمان بازبودن تونل، [فروشگاه](http://127.0.0.1:13000/fa) و [پنل](http://127.0.0.1:13173/) از همان دستگاه باز می‌شوند. مدیر MFA را در اولین ورود در پنل تکمیل می‌کند. نشانی‌های عمومی HTTPS پس از پذیرش گواهی و به‌روزرسانی originها استفاده می‌شوند.

## انتشار نسخه با تگ

تغییرات مجاز را به شاخهٔ `codex/arvan-test-deploy` بفرستید. یک تگ جدید مانند `test-v0.1.1` روی commit همان شاخه بزنید و تگ را push کنید. workflow مستقل آزمون، هر سه تصویر را روی Runner میزبانی‌شدهٔ GitHub می‌سازد. کش هر برنامه در GHCR جداست. ماشین آروان فقط digestهای نسخه را دریافت می‌کند و روی آن build انجام نمی‌شود.

- متغیر `ARVAN_TEST_STOREFRONT_URL` را به origin HTTPS فروشگاه آن نصب تنظیم کنید. پنل هنگام build همین نشانی را می‌گیرد.
- Runner سرور را با کاربر مستقل و label اختصاصی `arvan-test-deploy` به همان مخزن خصوصی ثبت کنید. Runner عضو گروه Docker نیست.
- روی هر میزبان `compose.yaml`، قالب Nginx و `deploy.env` را در `/opt/sayman/shared/deploy` با مالک root قرار دهید. مسیر گواهی در `SAYMAN_TLS_DIR` تعیین می‌شود. دادهٔ نمونه در Git نسخه‌بندی می‌شود و volume، backup و کلیدها روی میزبان می‌مانند.
- `ARVAN_TEST_AUTO_DEPLOY` فقط پس از تأیید دسترسی اجرای فرمان ثابت `/usr/local/sbin/sayman-arvan-release` فعال می‌شود. نسخهٔ root-owned همان `release.py` است. فرمان، commit و سه digest محدودهٔ مخزن را کنترل می‌کند، بکاپ و migration را انجام می‌دهد و بعد از بررسی سلامت نسخه را ثبت می‌کند. لاگ‌ها چرخشی‌اند و حداکثر دو نسخهٔ موفق قبلی برای تصاویر ثبت‌شده نگه داشته می‌شوند. حجم دیتابیس و بکاپ‌ها از پاک‌سازی تصویر جدا هستند.

برای نصب مشابه، گواهی و IP مجاز را مستقل بسازید و نام‌های میزبان را تغییر دهید. اگر نصب هم‌زمان روی میزبان دیگری لازم است، label و مقصد workflow را هم جدا کنید تا هر تگ فقط روی میزبان موردنظر اجرا شود.
